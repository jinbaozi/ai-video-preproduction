# 七技能协作工作流 V6

## 新项目的执行入口

新项目默认使用 `orchestration_protocol=6.0` 和 Codex 专业智能体。内核从 [唯一工作流定义](workflow-v6.json) 判定阶段、输入、责任角色、专业 Skill、检查与适用条件；`run` 返回待执行宿主动作。Codex 宿主实际派发专业子智能体，登记工具回执、消息、候选结果和独立审阅，再由内核决定状态。Python 不自行启动子智能体，聊天回复也不改变项目状态。协议、CLI 和恢复规则见 [V6 执行接口](references/v6/runtime.md)，真实工具回执与不确定派发的处理见 [Codex 宿主桥接](references/v6/codex-host.md)。

每个子智能体只处理任务信封划定的范围：读取冻结输入与锁定模块，写入自身候选目录，提交真实文件哈希、检查结果和交接映射。独立审阅者检查候选文件与全部要求，不能由创作者审结自己的结果。内核独占正式产物登记和状态提交；`ACCEPTED` 需要协议、版本、执行身份、依赖、专业检查、审阅与交接全部通过。需要跳过的节点须有 `NOT_APPLICABLE` 记录，不能靠缺少任务隐式跳过。

任务异常按原批次核对与恢复。派发状态不明、工具执行后失联或媒体结果未知时，先查询既有任务或调用；不得凭超时重新派发或重复生成。图像提示词由 image-prompt-optimizer 专业任务完成，图像工具调用是单独宿主任务。`production_target=video` 的完成门绑定实收 Take、逐镜与相邻验收、总装及整片审阅的当前文件字节。

V6 候选仍携带冻结 V5 任务对应的原生 IR 和 `role-result/5.1`，并通过模块收据及原生校验；提交路径必须是 V6 的 `agent-result`、独立审阅和状态门。下文 V5.4 的当前 Agent 循环及 `submit` 等旧命令只适用于旧协议项目，或显式选择 `--orchestration current-agent` 的新项目。

## V5.4 旧协议执行合同

## 当前执行合同

按任务读取 [当前执行合同](references/current-contract.md)，不要逐版阅读 V5.1/V5.2。本入口负责项目状态：资料与锁定、任务、前期交付、视频执行记录和验收。空间读「空间」，动作读「动作」，声音读「声音」，投喂读「渠道」。

`delivery=full|text-only` 仍只表示前期包是否包含实际参考图。`production_target=none` 到前期 `DELIVERED` 结束；`production_target=video` 还要真实 Take、镜头/相邻/整段验收和总装通过，才是 `VIDEO_DELIVERED`。历史合同在 [references/history](references/history)。

轻量任务直接交付正文。完整制作使用原生 1.2。读取旧包不等于达到当前标准。


用户提供资料即可开始。当前 Agent 依阶段使用专业模块，不切换固定模型，不要求子 Agent。
只加载当前任务、所需上游切片和对应专业说明。原文事实、稳定 ID、资产版本与用户决定由项目持有。

## 每任务固定循环（硬门）

`workflow_release=0.10.0` 的项目，带专业模块的任务必须按下面五步做完才能 `submit`。缺任何一步就不要提交。

1. `run` 取得当前任务。返回里的 `required_reads` 是本任务必读清单。
2. 完整读取 `task.module.path/SKILL.md`，以及清单里按任务类型列出的 reference。读的是任务信封给出的锁定副本，不是仓库里另一份同名文件。
3. 按该模块自己的输出契约创作。image-prompt 至少要有需求理解、主提示词、生成参数、质量检查，以及逐条对应本 job 锁定项的 `checks`。身份参考图还要有通过 `validate_production_contract.py` 的制作合同。
4. 提交 RoleResult 5.1，并附 `module_receipt`：`name`、`version`、`skill_sha256`，以及实际读过的 `reads[{path, sha256}]`。哈希必须与清单一致。
5. 内核核对收据、锁定项覆盖和宿主登记。核对失败就改结果再提交，不要换一条绕过路径。

禁止：

- 把其他项目的 `build/`、`authored/`、提示词或 `checks` 当创作来源。只允许对照 Schema 字段名。
- 把 `visual_review` 的结论写死。看图结论必须逐条对应 job 的锁定项，并来自实际打开的图片。
- 使用其他应用的凭证、私有接口或未登记工具生图。`call_evidence` 里的工具名必须在 `host.image_tools` 中，`provider` 必须在已登记列表中。

用户指定的图像模型不在已登记宿主能力里时，用 `request-decision`（kind=`capability`）说明当前宿主实际有什么，并让用户选择。不要自行寻找旁路。

`workflow_release` 早于 0.9.0 的项目仍接受 RoleResult 5.0。没有 `module_receipt` 的结果记为未审计，不能当成已按模块执行。收据只证明用了哪份锁定资料，不证明理解质量；质量由模块校验器、编译复核和验收把关。

## 执行

1. 读 [V5 执行接口](references/v5/runtime.md)，定位项目；旧项目只读，需续作时复制迁移。
2. `run` 返回任务信封后，读取其中的模块 `SKILL.md` 及本任务所需资源，当前 Agent 完成任务并 `submit`。CLI不创作自然语言，也不调用图像工具。
3. 专业能力仍是资料 → 故事剧本 → 导演 → 美术 → 视觉资产 → 分镜 → 分镜图 → 编译 → 验收，但不是每次都走完。先做路线预检和当前镜头真正消费的锚点。`text-only` 不启动生图。`production_target=video` 时，前期 `DELIVERED` 之后用 `production` 冻结、执行或回收、验收、总装。
4. 生图先使用锁定的 image-prompt-optimizer 完成提示词及约束检查，再由宿主真实图像工具执行；保留图片、实际输入绑定、调用记录与看图结论。先 `begin-image` 再调用；中断后回收原结果，不能盲目重生成。
5. 角色身份首次定稿只展示实际图片和必要决定；用户已明确选择直接记录，不重复询问。普通检查与修订自动继续。
6. 独立制作包用 `import-artifact` 接入，核对原生协议和来源后复用；镜头、实体、空间、台词或锁定项冲突交回原所有者。新 AVIR 1.2 编译正文按镜头与时间排列，完整合同仍留在制作说明和审计覆盖中；再依模型单次时长生成独立提示词文件，每份都包含所需图片引用与细节，阻塞片段不能作为已通过的投喂文件；既有项目模块锁不自动迁移。
7. `validate --final` 与 `export` 通过后交付实际参考图、可复制提示词及附件表。缺依赖只能交付明确的草稿，不能称为完成。

## 专业职责

- screenplay-grammar：独立故事、剧本、因果、人物认知、信息揭示约束和台词；也支持中文与国风补全、润色、扩写。
- director-grammar：落实编剧约束的视听设计、表演与已锁定镜头；分镜细化未锁部分。
- production-design-grammar：世界、场景拓扑、服化道、材质、世界光源；不重写镜头和台词。
- storyboard-grammar：镜头、画格、时序、连续性；保留上游锁定项。
- video-prompt-compiler：组合流程唯一模型编译出口；不借优化改变创作决定。
- image-prompt-optimizer：静态图片提示词与编辑指令；不直接生图。

## 交付与边界

保留真实文件名、稳定 ID、哈希、用途和实际附件顺序。对白写作 `说话人：“台词内容”`；旁白、画外音与静默心理不能换归属。
表演正文按触发→可见反应→动作/接触→反馈→收束组织，按景别和时长选择微表情、手部、重心与声音细节。
编译采用冻结结构；语义改动创建新修订。修改单镜沿动作、声音和引用的实际依赖检查连续性，换模型不自动重做角色图。
摄影数值和坐标是制作意图；实际入口未证明的控制、槽位和媒体属性不能写成已执行能力。

Python 3.12+；纯文本制作不需要媒体工具，真实图片登记需 ffmpeg/ffprobe 和宿主生图/导入能力。
本包包含六个与独立发行包字节一致的锁定模块，无同级源码运行依赖。详见 [模块和发行](references/v5/modules.md)、[交接与验收](references/v5/contracts.md)、[迁移](references/v5/migration.md)。

## 编剧原生接入

第二阶段使用锁定 screenplay-grammar；新项目必须通过 ScriptIR 原生校验与内容指纹复核。编剧新增实体先由 Canon 所有者登记，再重绑主稿；导演交回每条硬要求的映射。旧五模块项目按旧锁继续，显式升级后旧剧本进入待结构化状态。纯剧本请求直接使用独立技能；text-only 仍指现有前期制作流程不生图。
