# 阶段质量、专业路由与如实报告

适用：0.20.1 起新建的 studio 项目，冻结 quality_policy=studio-quality/1.0。旧项目不静默迁移，不把旧对话变成已接受收据。此合同不新增 Agent、不要求用户填表；由当前宿主连续执行。

## 默认选人与真实采用

默认 craft-routing auto。Canon 基于来源提交四项职责的检索特征；编剧、导演、美术和分镜调用已有登记路由。存在适用人物时报告实际 practitioner，否则报告方法/语法，不硬凑人名。图像、AVIR、编译复核继承上游方法并使用本模块提示词方法，不等于再选一个导演。来源、选择依据、规则、采用正文指针和发现保留在原任务/结果中。选择过不等于采用过；禁止事后补名。

只读取当前选中的必要规则，不全库展开，不写重复方法论文。显式 off 是关闭路由，不是降低专业完整性；仍须通过 quality_review。status 的 stage_report 区分 SELECTED_NOT_ADOPTED、ACCEPTED_HOST_DECLARED、NOT_RECORDED 和 STALE_OR_UNREVIEWED。单宿主自审不能称为独立专家交叉审核。

## 剧本先检查生活因果

每个原生 narrative.events 事件逐项检查：

1. knowledge_trigger：此前知道什么、何时获得什么信息；信息必须先于反应。
2. motivation：为什么在此刻采取这一行动，目标与选择是否一致；不能把“可能发生”当成“正文已交代”。
3. time_order：前后顺序、耗时和省略范围；准备、移动、换装等不能凭空完成。草案时长与真实音频实测分开。
4. resource_origin：食物、杯子、服装、手机等从哪里来，谁准备，何时可用，谁持有；无相关物件时解释不适用，不能机械编造道具。

反例：准备出门→找手机→发现周六→吃已经摆好的早餐，未交代为何备好却不吃。并非“准备出门的人一定吃过早餐”，而是本故事缺少行为理由和物件前置状态。
可行修法：先备早餐→误以为迟到而放弃吃→拿包去玄关换鞋→看到手机日期为周六→返回已备早餐。手机触发日历认知，不能一边写想起、一边没有可读的信息镜头。该例只说明检查方法，不是自动改写所有用户剧本的模板。

宿主发现缺口：在原生正文修订后重新审核；未解决则 FAIL 或 unresolved，停止受影响下游。不得靠“片刻后”或详细食物提示词掩盖因果缺口。

## 导演、美术、图像、分镜与编译

导演：逐镜检查上游因果的可见实现，区分世界/画面/身体左右、机位/身体/视线，声音先于反应；屏幕朝人物时须明确观众如何看到日期。
美术：身份锚点、造型变量、瞬时状态分离；参考职责与禁止继承项明确；道具用途、来源、归属、材质、光源和空间拓扑有依据。
图像：完整描述当前可见且有用的面容/发型/服饰、构图、姿态、唯一视线、接触、遮挡和光线；单张只表达一个瞬间。每张实际参考需先看到。401、链接未读、未生成均不等于已绑定身份。
分镜：每镜目的、景别、机位、起始状态、动作顺序、主体/相机运动、声音、时间依据、结束状态和切点齐全。持稳参考不能冒充拿起前首帧；关键帧不是动作成功证明。
视频：完整逐段正文、入口版本/模式、参数、附件职责、音轨和可用时长分开。Flow、Vids、RunningHub 是平台名，不能据此猜底层模型能力。未知参数保持阻塞，允许先完成带待核验标记的文字草案，不称最终模型包。

不以字数衡量质量，也不以“写实、8K、同一个人物”代替制作约束。用户要求详细时，交完整规格、可复制正文、附件映射和验收要点；简化展示不删内容。多人/多视图/控制资产只按实际用途制作。

## quality_review：同一结果内的证据，不是第二份剧本

运行时 task.quality_contract 给出当前检查集合和范围。编剧每个 /narrative/events/N，导演/分镜每个 /shots/N（无 shots 时每个 /scenes/N）；其他阶段根范围为空字符串。每个范围的每个检查都需要一个 finding。正文位置和引用必须真实存在，范围内至少一条证据落在本事件/镜头内。

```json
{
  "quality_review": {
    "policy": "studio-quality/1.0",
    "findings": [{
      "scope": "/narrative/events/0",
      "check": "resource_origin",
      "status": "PASS",
      "finding": "正文先交代准备早餐，再因误以为迟到放弃用餐；食物不是在后镜突然出现。",
      "evidence": [{"pointer":"/narrative/events/0/description","quote":"先备好早餐"}]
    }]
  }
}
```

这是单项结构示例，不是完整可提交审核。字段/引用须按实际正文填写。core-result 由运行时绑定 artifact_sha256；完整 role-result 需带实际字节哈希。证据缺项、重复、错误引用、失败结论、旧哈希均阻止接受。程序验证覆盖与绑定，不推断 finding 是否聪明，也不自动生成 PASS。结构有效、HOST_DECLARED 语义、真实媒体验收分别报告。

## 阶段、修订与外部工具

只有已接受的原生结果才能成为正式下游依据。导演/美术未提交时，在聊天里画图只能称探索，不得登记为已验收下游资产。真实图片通过原生 image 任务绑定输入、调用证据、字节和实际视觉审阅，不能仅凭对话图片冒充阶段完成。

用户新参考、剧情、手别或造型变化：先保留来源，交回拥有者，通过既有 revise/step 创建修订，保留旧版；依赖指纹使受影响下游失效。不能直接修改已接受JSON，也不能为迁就生成错误自行反转已锁定手别。独立探索允许，但必须保持未入库/未验收标记。冻结生产policy/manifest的任意重基仍未实现，需重规划相应生产范围，不能宣称聊天更改已经传播。

报告必须来自当前状态与收据：哪些角色已选、哪些已采用、哪些原生提交通过、媒体实际生成/验收与费用分别列明。不以“完整包”指代仍缺权威产物、真实引用或模型参数的草案。缺条件时交已完成内容、明确阻塞和恢复入口；恢复不重提 UNKNOWN 任务。

## 适用风险试制

canary 只映射实际适用风险到已计划镜头。同一复杂镜头可覆盖多个风险。五镜以上，未映射的类别必须提交 risk_exclusions；每项含 reason、全部已计划 shot_ids、proof_file（真实审阅依据）。证据字节被冻结并在支出前重验，不适用的宿主判断不是程序自动发现。

```json
{"risk_exclusions":{"two_speakers":{"reason":"全片只有一位说话人，已逐镜审阅。","shot_ids":["实际全片镜头ID"],"proof_file":"/absolute/actual-risk-review.json"}}}
```

示例不是可直接提交的全配置。不足五镜仍试制全部镜头；至少保留一个适用试镜，未通过原生选片/验收不放行批量。保留既有预算、结算和UNKNOWN保护；不把未报价记为免费。

## 旧项目恢复

新版本不会给旧项目补造专业选择或质量证明。status 显示旧 craft_policy/quality_policy。已有未验收探索素材可以保留；如需新质量门，创建新的 studio 项目，带原来源/修订简报，逐阶段重新提交真实内容与审核，媒体在匹配任务中以 provided 导入。不能手改project.json假装升级完成，也不重新收费生成已可复用的素材。
