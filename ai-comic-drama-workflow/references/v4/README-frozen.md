# AI 漫剧工作流 V4

专为 Codex：把小说、剧本、文字或分镜，制作成带真实角色参考图与故事板图的视频提示词包。

## 新用户只需这样说

```text
使用 $ai-comic-drama-workflow，根据我提供的资料制作双图视频提示词包。自动完成各阶段，只在必要选择、角色定稿或风险问题时让我确认；保留原剧情，图片按资产名命名，提示词明确引用对应参考图。
```

附上资料即可。已有剧本、分镜优先复用，不强制从小说重写。

## 十阶段

资料准备 → 生成大纲 → 修订大纲 → 剧本生成 → 剧本精修 → 时长切片 → 分镜 → 美术资产生成 → 空间站位与故事板 → 视频提示词。

每阶段有独立编号目录；JSON是机器事实源，Markdown用于查看。修改上游后重检受影响下游，保留历史图片与版本。

- 阶段1—8：GPT-5.6 Luna / max。
- 阶段9—10：GPT-6 Astra / medium。
- 图片：Codex原生image_gen；不是Luna或Astra直接生图。
- 不需要Blender或FFmpeg，不生成视频、不做配音剪辑、不发布。

仅在缺少风格/画幅、核心剧情冲突、权利或费用授权、角色身份首次定稿、能力不足或无法安全修复时暂停。普通大纲修订、剧本精修、空间与故事板审核自动继续。

## 交付物

图片示例：`沈知微_常服_正面_v001.png`。提示词引用：`@image_role_1`。附件表将别名绑定到真实文件名、路径、版本、哈希和用途；故事板图使用`@image_board_1`等别名。

角色镜头必须同时绑定角色图和故事板成图；每镜实际引用最多5张。图片缺失、版本过期或未定稿身份不能通过正式交付。草稿必须明确标记，不能当成完整双图包。

别名不保证所有视频平台原生识别，目标平台上传方式仍需验证；本项目完成的是提示词包，不是最终视频。

## 维护与验收

内部操作见 [Codex执行接口](references/v4/runtime.md)。使用Python3.12；运行 `python scripts/run_tests.py` 验证，`python scripts/package_skill.py` 打包。

旧项目只读或复制为新V4项目，不静默覆盖。保留旧版模块及测试作为兼容证据，但V4活动工作流不运行旧媒体执行器。

本轮按用户要求只做代码验收，不执行真实生图；版本为0.4.0候选，不创建正式v0.4.0发布标签。具体结果见 [V4实施记录](docs/implementation-v0.4.0.md)。
