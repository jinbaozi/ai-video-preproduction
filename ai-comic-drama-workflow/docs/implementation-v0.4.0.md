## 实际实现

- 十阶段正式目录和JSON/Markdown同源视图；上下游按依赖闭包失效，镜头/资产输入哈希控制图片复用。
- Luna/max与Astra/medium写入每个TaskEnvelope；宿主须提供真实派发记录，不允许换模型。纯Python只能派发与验证宿主回执，不能自行证明模型或原生生图可用。
- 用户初始明确指定的风格、画幅、权利、图片额度直接留痕，不重复询问；普通文本、空间与故事板质量检查自动继续。
- 角色批准绑定任务输入、图片版本及SHA，不仅绑定像素；同名文件内容变化使相关批准与下游失效。
- 图片按资产名命名；规范化重名追加短ID；@image别名稳定分配。角色与故事板真实文件共同绑定，保留全部逻辑依赖。
- 轻量空间、人物动作/情绪/摄影/声音时序；故事板任务只描述选定瞬间，原生调用必须实际传入角色图。无Blender、骨骼或物理仿真验收要求。
- 模型创作/审查按最多5镜批次，草稿在runtime暂存，全部验证后提交正式产物。失败最多3次技术重试、2次创意返修；不确定响应直接暂停。
- 视频提示词包含时码、完整Canonical控制字段、逐字段覆盖、参考附件和来源哈希；最终导出重新校验，不把提示词包说成视频。
- 旧项目只读或复制，不原地迁移；原文件保存在新项目.history/migrations，旧批准不复用。旧图片保留为候选，须按V4重新导入/验证，不自动视为已批准。

本轮用户明确选择“只做代码验收”：不调用真实image_gen，不做真实图像质量验收，不创建`v0.4.0`正式标签。
