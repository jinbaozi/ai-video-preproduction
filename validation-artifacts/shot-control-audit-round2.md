## A01 · P1：合法原生 `reference` 合同使 `lower()` 崩溃

**位置：**`control_lowering.py:140–143`；相关限制还在 `package.py:35–36`。

**最小复现：**在完整原生项目中添加合法的 `reference` 合同，并提供对应原生 asset／binding。原生校验、`build`、`verify` 均通过，再调用 `lower()`。案例：`N01_native_reference`。

**实际结果：**

```text
KeyError: 'reference'
```

主义务映射只处理：

```python
{
    "prompt": "prompt",
    "parameter": "native_parameter",
    "post": "post_production"
}
```

遗漏了原生协议支持的 `reference`。此外，若尝试让该 `reference` 合同关联控制项，配置校验又将其归入不可接受的通道。 

**预期结果：**原生合法通道都应有明确的转换结果或结构化未支持诊断，不能因为增加了一条合法合同而使整个降译崩溃，也不能要求用户把 `reference` 改写成 `prompt` 来绕过。

**建议修复：**穷尽原生合同通道，为 `reference` 建立独立的待编译义务；将“能否作为 supplement”与“是否已经执行主义务”分别判断。

**验收条件：**同一完整原生包同时包含 `prompt`、`parameter`、`reference`、`post` 时，能返回状态明确的降译结果；未实施部分仍保持 `NOT_COMPILED`。

## A02 · P1：职责标签可以降低时序配方依赖，绕过 FOV 失效

**位置：**`package.py:80–98`，特别是 `84–85`；`control_lowering.py:54–58、72–84`。

**最小复现：**使用同一个真实的 4 秒合成 MP4，通过 `clay_video_reference` 输入，比较两种资产标签：

| 条件 | 修改 FOV、重建原生控制包后的结果 |
|---|---|
| `role=clay` | `STALE_ASSET_RECIPE`，被阻断 |
| `role=identity` | 仍为 `BOUND_DRAFT` |

案例：`N02_temporal_role_clay`、`N02_temporal_role_identity`。

**原因：**`recipe()` 对 `identity / appearance / style` 跳过了机位、时段和动作依赖；而 `lower()` 没有根据**实际消费通道**强制补上这些依赖，也未拒绝这组有问题的 `kind / role / channel` 组合。 

**预期结果：**一个视频被用于时序／机位参考时，不能因为资产清单里填了“身份”标签，就不受 FOV、crop 或轨迹变化影响。

**建议修复：**建立 `kind × role × channel` 兼容表。配方依赖取“资产职责”和“消费通道”的并集，而不是只由 `role` 决定。时序通道必须包含其所需的机位、动作和时间映射。

**验收条件：**身份、造型、风格标签均不能使时序视频绕过失效检查；合法静态身份图仍能在无关改动后复用。

## A03 · P1：URL 的 `#fragment` 可以绕过全局内容冲突

**位置：**`control_lowering.py:87–95`。

**最小复现：**给不同哈希的两张 PNG 分别绑定：

```text
https://example.com/shared.png#identity-a
https://example.com/shared.png#identity-b
```

完整原生包及资产其他条件均满足。案例：`N09_url_fragment_alias`。

**实际结果：**返回 `BOUND_DRAFT`，没有 `URL_CONTENT_CONFLICT`。本地标准库解析确认，两者的 HTTP 请求目标都是：

```text
/shared.png
```

本次没有向该地址发出请求。

**原因：**全局 URL→hash 表采用原始 URL 字符串作为键；fragment 让字符串不同，却没有形成不同的 HTTP 获取目标。当前修复只挡住了“字符串完全相同”的形式。

**预期结果：**相同获取资源不能同时声明为两个不同的内容版本。

**建议修复：**禁止素材 URL 带 fragment，或使用去掉 fragment 后的传输标识检查冲突，并保留原字符串用于审计。**不要顺便删除 query**：`?v=a` 与 `?v=b` 可能代表不同资源，本轮对应正例保持可用。

**验收条件：**fragment 变体被阻断；不同 query 的独立资源可以通过；同内容多职责的编号与预算仍一致。

## A04 · P2：关键帧检查和 `lower()` 对同一用途的时段校验不一致

**位置：**`keyframes.py:42–49`；对照 `control_lowering.py:70–84`。

**最小复现：**项目总长 8 秒，S1 为 `0–4000 ms`。从 `build` 生成的 S1 关键帧请求出发，为真实身份 PNG 提供：

```text
shot_id = S1
start_ms = 9000
end_ms = 10000
```

配方及用途审核摘要与这份声明一致。案例：`N04_anchor_time_scope`。

**实际结果：**

```text
keyframe-check：
DRAFT_REQUIRES_HOST_REVIEW
reasons = []

lower：
BLOCKED
ASSET_TIME_SCOPE
```

关键帧检查验证了镜头存在和配方，却没有复用 `lower()` 的时段边界规则。 

**预期结果：**同一份不合法用途，应在两个消费者中被一致阻断。这不是图片质量已经“通过”的漏洞，而是一个可确定的结构错误从关键帧入口漏过。

**建议修复：**提取共享的资产用途验证器，统一检查镜头、时段、职责、配方和审核绑定；各消费者只追加自身规则。

**验收条件：**越界、倒序、错镜头的用途在 `keyframe-check` 和 `lower` 中得到一致结论，合法主参考复用不被误伤。

## A05 · P2：审阅 HTML／SVG 改内容并重算哈希后，仍能获得 `VERIFIED`

**位置：**`package.py:63–73`。

**最小复现：**先构建有效包，再将下列任一文件中的角色标记 `NA` 改成 `MISLABELED_ACTOR`：

```text
review/index.html
review/blocking-001.svg
```

只更新该文件的清单哈希，不改 AVIR、配置、预览 JSON 或其他权威数据。案例：`N03_review_reseal_html`、`N03_review_reseal_svg`。

**实际结果：**`verify_package()` 接受。

当前会重新派生并比较四类 JSON，但审阅 HTML／SVG 只检查其是否符合清单哈希。

**预期结果：**声称“同源调度审阅”的画面与权威数据不一致时，不能获得完整包验证成功状态。

这里不是要求一个未签名本地包抵抗能改写全部权威源的攻击者；本例的权威源未变，问题是**派生内容没有全部参与一致性检查**。

**建议修复：**对确定性 HTML／SVG 重渲染并比较；或者由可信模板直接消费已验证结构。允许人工注记时，注记应与权威派生画面分开存储。

**验收条件：**人物标记、路线、时码被修改后，即使重算清单也能识别；原样重复构建保持一致。

## A06 · P2：原生输出画幅与冻结评价基线可以相互矛盾

**位置：**`package.py:17–24`；`control_plan.py:46–49`；`media_review.py:16–18、35–40`。

**最小复现：**原生输出为 `9:16`，并增加一条要求 `9:16` 的原生硬参数断言；控制配置中的 lens 仍设置为 `16:9`。原生校验、`build`、`verify` 均成功。再用真实 `320×180`、8 秒 MP4 和对应合成测量调用评价。案例：`N06_aspect_conflict`。

## A07 · P2：原生合法的非整数毫秒事件，无法导出控制包

## A09 · P2：配方依赖整镜和全部实体，导致无关变化使首帧失效

**位置：**`package.py:89–97`。

**最小复现：**保留 S1、`0 ms` 的干净首帧及审核记录，分别创建两个原生有效的新版本：

| 改动 | 0 ms 的画面点／瞬时状态 | 旧首帧结果 |

| 修改一个不出镜、不参与轨道的实体外观 | 不变 | `STALE_ASSET_RECIPE` |

## A10 · P3：竖屏比例修好了，但画框边缘的角色标签被裁切

**最小复现：**打开有效 `P12_portrait` 包的生成页面，在三种测试宽度下检查摄影机 SVG。

# 六、建议的修复顺序与最终判断

建议第一批处理 **A01、A02、A03**：穷尽原生通道、禁止职责标签降低时序依赖、按实际 URL 获取目标检查内容冲突。它们分别影响合法输入可用性、资产失效正确性和最终附件可信性。

第二批闭合 **A04—A08**：统一各消费者的用途验证，覆盖审阅派生文件的一致性，解决画幅权威冲突、时间精度和投影失败传播。A09 明确并改进适用性粒度；A10 修复标注布局。

**本轮补丁结论仍是 `Request changes`，但不是上一轮问题原封不动。**媒体与主义务分离、完全相同 URL 的冲突、冻结评价 JSON、空包检查、去重预算、音频总量和竖屏比例，都已经有独立复跑支持。现在的问题集中在：**合法类型没有穷尽、同一不变量没有覆盖所有消费者，以及字段标签仍能影响本不应被削弱的依赖。**

**整体交付仍未完成，应继续单独验收。**下一轮先让本报告的失败断言得到修复，再独立运行原仓库回归和发行包检查；在联合编译和真实执行证据出现之前，继续保留 `NOT_COMPILED`、`NOT_RUN`，不要用任何测试数量替代它们。
