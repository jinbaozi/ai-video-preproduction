# 制作合同填写模板

由 Agent 将资料转入 [原生 Schema](../schemas/production-contract.schema.json)。可复制 [已填实例](../examples/production-contract.json) 的结构，但必须替换示例事实和来源，不复制示例为真实用户要求。简单任务可用以下简版；需要机器校验时用 JSON。

## 简版（同样保留五项）

1. **来源**：用户原话/文档章节/真实参考文件名；哪些是观察、推导或默认。
2. **结构**：交付类型、主体 ID、场景、画幅、逐帧动作、空间与文字归属。
3. **约束**：必须出现、必须保持、允许变化、不得出现；每条编号并绑定来源。
4. **执行路径**：正文编译 → 参数核验 → 执行者与输入附件 → 成品检查；本次未执行的阶段标明 NOT_RUN。
5. **验收**：每条硬要求的正文片段、检查方法、通过标准、当前证据与状态。

## 完整包

默认文件建议（遵从用户指定目录/文件名）：

- `production-contract.json`：来源、ICIR、硬软约束、编译版本、执行路径及检查记录。
- `prompt.md`：一条或按目标分开的可复制正文；正文外列真实文件名与绑定顺序，API 参数单列。
- 已有结果时可补 `review.md`：可见问题、相关合同条目、修订范围与真实文件证据。

无需额外报告时将 trace/checks 留在合同，避免重复三份内容。用户只要提示词时不额外建立完整包。文件名或外部任务 schema 由上游指定时保持原契约，不发明兼容字段。

## 交付检查

执行 `python3 scripts/validate_production_contract.py <合同路径>`；修订再加 `--baseline <旧合同>`。若仅验证结构，通过状态为 `STATIC_VALID`，不是“成图合格”。语义审查另看每个来源和正文是否等义；没有结果图，视觉验收项保持 NOT_RUN。对图像执行的委托说明应保留实际参考槽位、已核验参数及明确停止条件。
