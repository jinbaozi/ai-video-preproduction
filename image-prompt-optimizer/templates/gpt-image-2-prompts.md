# GPT-Image-2 提示词模板

只在目标为 GPT-Image-2／ChatGPT Images 2.0 时使用。先判断文生图、参考图引导的新图、整体编辑、遮罩编辑、多图合成或连续修订，再选择一个模板；删除所有不适用字段，参数不写进主提示词。

## 目录

1. 简洁通用生成
2. 复杂结构化生成
3. 参考图引导的新图
4. 基图编辑合同
5. 遮罩局部编辑
6. 多图合成
7. 写实人像附加模块
8. 局部修订
9. 精确文字与版式
10. API 参数与 4K

## 1. 简洁通用生成

```text
为<用途／渠道>生成一张<照片／插画／3D 产品图／海报／其他交付物>：<场景／背景>中，<第一主体>正在<唯一动作或状态>，<只写会改变结果的关键外观、产品、物件或关系>。采用<景别／视点／构图／留白>，<主光或主要色彩与材质>；必须<1—2 个硬要求>，除<精确允许项>外不出现<额外人物／物件／文字／标志／水印>。
```

保持 1—3 个完整句子。若用户提示已具体，只整理顺序与冲突，不擅自补故事、品牌、人物、文案或装饰。

## 2. 复杂结构化生成

```text
任务与用途：<渠道、交付物、受众或阅读距离>。
场景与背景：<空间、时段、前中后景、背景复杂度与安全区>。
主体与事件：<第一主体、唯一动作；次级对象及其关系>。
关键细节：<人物／产品／界面／图表中会改变验收的属性>。
构图与版式：<画面方向、视点、主体位置、裁切、组件数量、层级与阅读顺序>。
光线、色彩与材质：<主光、主色、对比、表面和媒介特征>。
精确文字：<逐字文案、字体类别、颜色、位置、对齐；无文字则删除>。
约束：<少量必须出现、不得出现和不可改变的硬门>。
```

产品任务把几何、部件、标签、固有色和材质放在“关键细节”；信息图、UI、海报和多面板把组件数量、文字和阅读顺序放在“构图与版式”。

## 3. 参考图引导的新图

```text
使用输入图作为新画面的参考，不编辑任何一张输入图的原有构图。图 1：<身份／产品／物件>参考；图 2：<视觉特征／色彩／构图>参考；<更多图逐张定义单一主角色>。

生成一个全新的<交付物与场景>：保留图 1 的<明确可观察特征>，采用图 2 的<线条、色块、光比、材质或空间密度等可观察特征>，让<主体、动作、位置和关系>成立。<构图、光色、文字和少量约束>；不要复制输入图中未指定的背景、文字、标志或人物。
```

若用户其实要求“只改图 1”，切换到编辑合同，不能以“全新画面”替代基图保留。

## 4. 基图编辑合同

```text
编辑图 1。图 1 是待编辑基图并承载<身份／产品几何／姿态／构图／背景／光线>不变量；图 2 是<服装／产品／材质／视觉特征>参考。<更多图逐张定义角色。>

只允许改变：<完整列出用户要求的一个或多个兼容改动>。
必须保持不变：<只列本任务关键的身份、产品结构、姿态、机位、构图、背景、光线、文字或品牌项>。
融合要求：把图 2 的<元素>应用到图 1 的<位置>，匹配比例、透视、遮挡、材质、色温、接触和阴影；不得新增、删除、复制或重排其他元素。
验收：<目标改动可见；不变量无漂移；无编辑溢出>。
```

## 5. 遮罩局部编辑

```text
编辑图 1 的遮罩区域。本轮只<替换／删除／修复指定对象或属性>；遮罩只是区域指引，目标边界以<对象真实轮廓／接触边缘>为准。保持遮罩外的主体、身份／产品结构、几何、构图、文字、背景、光线、色彩和纹理不变；在边界处匹配现有透视、遮挡、颗粒、材质、反射、接触阴影和清晰度，不产生接缝、光晕或重复对象。
```

Image API 中遮罩使用带 alpha 的 PNG，并与第一张输入图尺寸相同；完全透明区域表示可编辑，非透明区域表示保留。多图编辑时遮罩作用于第一张输入图；它不是像素级硬边界，不承诺完全逐像素遵循。具体文件大小限制按当前 edits 请求参数核验。

## 6. 多图合成

```text
以图 1 为<基图／新画面构图参考>。从图 2 取<元素 A>放到<明确位置>；从图 3 取<元素 B>放到<明确位置>。保持<基图不变量或新画面要求>；让 A 与 B 的尺度、视点、透视、遮挡、光源方向、色温、材质、接触、反射和阴影属于同一画面。每个元素只出现一次，不错绑、不重复，不带入参考图的无关背景、文字、标志或人物。
```

## 7. 写实人像附加模块

把以下内容按可见性加入第 1、2、3 或 4 节，不单独堆成清单：

```text
<当前景别可见的身份锚点、发型发饰、服饰配饰>；<唯一动作、视线落点及眼周／嘴角／肩颈形成的表情>；<可信景别、机位和主要焦区>；<主光与肤色曝光锚>；<皮肤、发丝、手部接触、屏幕／玻璃或生活痕迹中最高风险的 1—2 项>。
```

双眼、手、屏幕、反射或景深不可见／不相关时整段删除相应要求。简单人像最终仍保持 1—3 句。

## 8. 局部修订

```text
继续编辑当前图像。本轮只<修复一个主问题；若不可分割则列出最小因果组>。保持<主体／身份／产品、数量、姿态、构图、机位、未涉及物件、文字、背景、光线、色彩、材质和已通过内容中的实际关键项>不变；不要新增、删除、复制、重排、重打光或重度重修其他区域。只校正与本轮目标直接相关的边缘、透视、接触、反射、清晰度或文字。
```

用户明确要求多个兼容改动时，把“本轮只”改为“本轮允许改变”并完整列出；不要因偏好单变量而静默删减。

## 9. 精确文字与版式

```text
交付物：<海报／信息图／UI／多面板>。必须包含<组件及准确数量>，按<网格／层级／阅读方向>排列。只出现以下文字，每项逐字呈现一次，不得增删、改写、重复、裁切、重叠或生成占位符：<按层级逐条引用文案>。字体：<类别、粗细、大小关系>；颜色：<颜色与对比>；位置：<区域与对齐>。除明确允许的既有品牌文字外，不出现其他文字、标志、二维码或水印。
```

信息图补充节点和连线归属；UI 补充屏幕状态、必需区块与主 CTA；多面板补充面板数量、每格事件、阅读顺序和连续性锚点。输出的“质量检查”必须写明：`发布前先用 OCR 提取全部文字，再人工逐字核对缺字、错字、重复、额外文字、裁切和重叠。` 关键资产再用设计工具精修。

## 10. API 参数与 4K

只在用户明确使用 Image API 或界面确实暴露等价字段时附加；参数必须按本次端点的当前官方 schema 复核。

```markdown
| 项目 | 建议值 | 说明 |
| --- | --- | --- |
| model | `gpt-image-2` | 保留用户指定名称；只有用户明确要求固定版本时才改用已核验快照；Responses API 不把它写进主模型字段 |
| size | `auto` 或经脚本校验的 `WIDTHxHEIGHT` | Image API generations／edits 支持灵活尺寸；Responses 按当前工具 schema |
| quality | `low`／`medium`／`high`／`auto` | 草稿用 low；身份、密集文字、近景和高分辨率成品比较 medium／high |
| output_format | `png`／`jpeg`／`webp` | 只按实际交付列出 |
| output_compression | 0—100 | 只用于 JPEG／WebP |
| background | `auto`／`opaque` | GPT-Image-2 不支持 transparent |
```

Image API generations／edits 的 4K 可在当前文档确认后使用 `3840x2160` 或 `2160x3840`，并标记实验性；主提示词不加入“4K／8K”魔法词。要求自定义尺寸时先运行 `python3 scripts/validate_gpt_image_2_size.py <WIDTHxHEIGHT>`。不要输出独立负面提示区，也不要输出 `input_fidelity`、`style`、seed、CFG、steps、采样器或 DALL·E `response_format=url`。
