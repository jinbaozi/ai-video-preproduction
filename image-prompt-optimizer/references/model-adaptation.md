# 模型适配

多后端语义编译及能力证据结构见 [后端编译](backend-lowering.md)。本文件旧型号表是有日期的历史快照；GPT Image 2.5 不继承 GPT-Image-2 的字段限制或尺寸脚本，用户指定旧模型仍保留其选择。2026-09-19 采用范围见 [研究采纳记录](research-adoption.md)。

本文件是易变信息的路由和核验协议，不是永久参数表。指定目标模型、版本、界面／API、负面提示或参考图方式时完整读取。只输出纯自然语言且无需声明当前能力时，可以采用已标注日期的本地模型卡；输出 API 字段、端点、尺寸、质量、参考图机制或其他易变能力前必须重新查官方文档。

## 1. 核验协议

1. 精确识别模型名称、版本、使用界面或 API 端点；同一模型家族的网页端、托管 API、本地工作流可能不同。
2. 保留用户指定的精确模型或别名；不得因为存在更新模型或固定快照就静默替换。只有用户要求固定版本／可复现性并确认取舍时，才改用已核验可用的快照。
3. 优先检索模型官方文档、API schema、模型页和发行说明。技术参数不以博客、社区提示词或第三方前端为证据。官方资料冲突时，按“当前 API 指南／API 参考或 schema → 模型页 → 官方 Cookbook 通用原则 → Cookbook 单个示例 → 社区经验”的顺序裁决。
4. 逐项确认：支持语言、提示词格式、独立负面字段、画幅／尺寸、质量、参考图输入、权重、seed、采样器及参数位置。
5. 把自然语言内容、负面约束、生成参数分开。参数值只来自当前端点的官方允许集合。
6. 记录核验日期和实际使用的直接链接。若官方资料缺失、冲突或无法访问，回退通用版并说明待调整项。

## 2. 通用回退

只输出中文自然语言主提示词。用“竖向人物构图、人物位于画面右三分之一、左侧留出干净文案空间”等内容描述替代模型命令。不要输出独立负面提示、尺寸、权重、采样器、CFG、seed 或任何 `--` 参数。

需要排除问题时先设计正向状态，例如把“不要僵硬”改为“肩颈放松、身体轻微转动、动作进行中的瞬间”。只有模型确认存在独立负面机制时再给精简负面字段。

以下仅帮助选择文档，使用前仍须复核。GPT-Image-2 行核验日期：2026-08-20；其他模型行沿用 2026-08-01 快照。

| 目标 | 当前安全适配 | 禁止混用 |
| --- | --- | --- |

## 4. 中英版本决策

- 默认给中文。
- 官方明确仅支持或推荐英文，或用户要求英文工作流时，再给自然、等义英文版本。
- 双语必须逐项对齐人物、动作、构图、光线、色彩、材质与限制；不要在英文版偷偷加入“masterpiece”“8K”等额外词。
- 若官方支持中文，不因社区传言强制英文。必要时说明英文版只是兼容选择，不声称必然提高质量。

## 5. 负面约束决策

- **无独立机制**：不创建“负面提示词”字段；在主提示词中用正向状态和少量自然语言限制。
- **有独立机制**：只列最可能破坏意图的少量问题，如“塑料磨皮、视线错位、手指结构异常、无关文字或标志”；不要复制几十项通用黑名单。
- **专属排除语法**：确认位置、解析方式和版本。Midjourney 的 `--no` 与 Stability 的 `negative_prompt` 不可互换。

## 6. 参考图决策

先说明每张图的用途：身份、服装、姿态、构图、场景、产品、色彩或整体视觉特征。不要让同一参考图同时承担互相冲突的角色。按编号写清来源图、目标图和空间关系；按目标模型的官方方法传图，不要把本地路径或 URL 当作所有模型都能理解的提示词内容。

涉及可识别真实人物、品牌或受版权保护资产时，执行授权检查；涉及“模仿某位在世摄影师”时，改写为可观察的构图、光线、色彩、颗粒和叙事特征。

## 7. 输出参数记录

使用简洁表格记录：`目标模型／版本`、`界面或 API`、`主提示词语言`、`负面机制`、`画幅或尺寸字段`、`参考图方式`、`待用户在界面调整项`、`官方来源与核验日期`。不输出未使用的字段。
