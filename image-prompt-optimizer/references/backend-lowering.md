# 能力驱动的后端编译

指定模型或多模型交付时，在 [模型核验协议](model-adaptation.md) 之后读取。来源与核验范围见 [研究采纳记录](research-adoption.md)。本文件是 Agent 编译规则，不是已经接通的生成适配器。

## 能力记录

每个目标保存精确模型/用户别名、vendor、surface（chat/api/local/export/generic）、核验日期、官方证据 ID、负面机制（inline/positive_only/separate/unknown）、允许原生参数键、参考输入方式与能力状态。UI、API 和本地工作流必须分别核验。能力未知仍可交付通用正文，参数为空；明确不支持的硬要求则阻断该目标。

参数证据应直接支持字段、值与端点组合，只有模型营销页不足以证明参数。运行校验器不会替代官方核验。参考路径只用于定位交付文件，不代表模型已上传或能读取本地路径。

## 降译规则

| 目标 | 正文组织 | 限制 |
| --- | --- | --- |
| GPT Image 家族 | 任务、主体、关键关系、构图、光色材质、保持/改动范围；完整自然语言 | 不沿用 SD 标签和权重；2.5 与旧 Image-2 的参数表分开核验；不因报告推荐而替换用户模型 |
| Gemini / Nano Banana | 主体动作、环境、视角、光线与可见细节；多参考逐张定义角色 | 精确型号、API/界面、多轮状态需核对；分轮编辑是可选策略，用户多个兼容修改不能静默删减 |
| FLUX.2 pro/max | 最重要主体、动作/空间硬项前置，后写风格和背景；负面概念转目标状态 | 官方指南采用正向表述，不输出独立 negative_prompt；30—80 英文词是建议而非硬上限，复杂硬合同可更长 |
| Qwen-Image | 中文意图、精确文字、身份与编辑锁分清 | 官方仓库本地示例存在 negative_prompt，不据此推断所有托管端点；外部 enhancer 的输出需重新过硬锁 diff |
| Seedream / Ideogram | 中文语义或任务布局优先，精确文字与组件关系明确 | 版本、授权、分辨率、参数待目标端点证实；不继承附件里的版本/能力宣称 |
| Midjourney | 人工导出的主提示词与已核验版本参数 | 不声称已接正式 API；不导出未经核验的尾部参数 |
| 未知/离线 | 保留完整自然语言和硬约束、单独列待核验项 | 不猜负面字段、seed、CFG、参考权重或尺寸档位 |

负面降译需要保持语义：多余人物 → 画面恰好两人；塑料皮肤 → 保留自然肤质与肤色层次；杂乱文字 → 画面仅包含用户指定文字集合。不能把“不要红色衣服”改成用户未指定的蓝色；使用“服装使用已指定的绿色”或保留排除约束，无法等义转译时记录问题。

每条硬约束在每份目标正文中都有 `constraint_clauses` 映射，映射值须为正文的原文片段。脚本只能验证片段存在，Agent 还须审查片段是否完整表达原要求，不能用无关片段冒充覆盖。原生参数另有能力证明；不能只在参数/日志里保留正文必须表达的视觉硬项。

## 版本与结果边界

适配器版本是本地规则版本，不是厂商模型版本。不同后端可以不同句序和词汇，但主体、计数、空间关系、精确文字和编辑不变量一致。不能承诺跨模型同脸或像素一致；参考绑定与结果 QA 才能提供相应证据。

搜索候选、价格路由、自动评图、500-case benchmark、训练和 HTTP 服务均不是本 Skill 当前实现。只有用户另行要求并有执行工具/预算时才开展真实实验，使用 [评价协议](compiler-evaluation.md)。
