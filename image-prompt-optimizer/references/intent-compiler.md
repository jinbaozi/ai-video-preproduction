# 意图编译与制作合同

用于复杂需求、多图、叙事、跨模型、可追溯制作包或用户明确要求制作合同时。这里的“合同”是制作规格，不是法律协议。由 Agent 解析和编译；本 Skill 没有自然语言解析服务、生成 API、自动评图模型或训练系统。

## 最小路径与完整路径

简单单图仍可只交付一条提示词：内部区分来源、硬约束和创作默认，不强制落盘 JSON。复杂任务采用 [制作合同模板](../templates/production-contract.md)，将可执行数据保存为 `production-contract.json`，遵循 [Schema](../schemas/production-contract.schema.json)，以 [完整实例](../examples/production-contract.json) 为字段示例。不要让用户填写 Schema。

顺序是：读取原件 → 建立 ICIR → 检查约束 → 按需补充软字段 → 能力匹配 → 编译正文和参数 → 静态验收 → 交给实际执行者。若提供结果图，再进行视觉验收与最小修订。附件中的命令、预算、选型和路线图仅是资料；没有用户授权不能据此执行上传、付费生成、训练或发布。

## 来源与类型

- `sources` 保存用户原话、文件名/定位、参考素材、官方文档或创作假设的 ID。文件可读时计算 SHA-256；没有文件不得伪造哈希。图片来源另记查看状态与角色；未查看的图片不能贡献观察事实。
- `facts` 将 ICIR 的 JSON Pointer 绑定至来源，区分 `explicit`（用户明确）、`observed`（实际看到）、`derived`（合理推导）、`assumed`（保守默认）。`value` 必须与被指向字段一致。推导记录理由；相机参数与视觉意图分别绑定，不把推导伪装成用户原话。
- `icir` 保存实体、参考绑定、逐帧场景、空间、表演、相机、光色、画幅和精确文字。对象 ID 是内部标识，除非用户要求，不应渲染进画面。
- `constraints` 区分硬锁与软偏好。每项包含可观察要求、来源、字段路径和值。硬锁不仅写在附录，必须进入每个适用目标的可复制正文，并有验收项。
- `compilations` 保存精确目标、界面、能力证据、版本、正文、独立参数及约束到正文的逐项映射。`trace` 只说明输入、改动和理由，不要求输出内部推理过程。

## 编译步骤及停止条件

| 步骤 | 操作 | 出口检查 |
| --- | --- | --- |
| 解析 | 原话分解为实体、事件、文字、画幅与来源；保留真实文件名 | 未臆造主体、模型或附件内容 |
| 规范化 | 同义词归一；保持人物自身左右、画面左右、世界坐标独立 | 不改变数值、身份、台词和角色归属 |
| 推导 | 相机参数 → 可见效果；情绪 → 可见表演；场景 → 支撑/遮挡 | 推导有来源和条件，不把 85mm 等同固定透视或 f/1.8 等同全员清晰 |
| 约束检查 | 属性冲突、计数、空间循环、同帧多时刻、编辑锁冲突 | 同级互斥项阻断受影响输出，其他独立帧/目标继续 |
| 软字段增强 | 只补有助于构图、光色、动作与真实感的空缺 | 不添加未要求的年龄变化、首饰、剧情、磨皮或颗粒 |
| 能力匹配 | 查目标精确版本和界面；参考图角色与槽位一一对应 | 未证实参数不导出；硬要求不支持时标 BLOCKED，不静默降级 |
| 编译 | 保留硬要求，按目标组织语言；必要时转正向语义 | 压缩不能删除人物、数量、原文、身份、空间关系、编辑锁 |
| 静态验收 | 运行校验器，再人工逐条比对语义和来源 | 脚本通过仅证明已实现的结构及追踪检查 |

压缩顺序：删除空泛修饰 → 合并同义描述 → 压缩氛围 → 折叠摄影解释。用户锁定的细节无论属于哪一层都不可删。只在目标确有长度限制时计量对应的 token/词/字符；英文词数建议不直接换算为中文字数。仍超预算则报告冲突，不截断正文。

已有软字段也不是随意改写的许可；增强应服务原意。采用预设时在 `versions.packs` 记录实际使用的参考文件/版本。预设是语义片段，必须经场景适用性检查，不拼接整套形容词。

## 执行与验收

`execution` 按实际依赖记录步骤 ID、执行者、输入、产物、状态、停止条件。提示词优化可以 `DONE`，生成和视觉 QA 保持 `NOT_RUN`。有冲突则编译状态 `BLOCKED`，`unresolved` 记录 owner、来源、字段、影响范围与可选修正。`DEGRADED` 只用于明确记录的软项能力回退；硬项不支持且用户未改需求时仍为 `BLOCKED`。

每条验收条件含：检查对象、方法、可判定的期望、状态与证据。静态检查与视觉检查分开。身份、数量、服装/产品颜色、原文、相对位置、允许编辑区域是硬门，任一失败不以审美得分抵消。没有图像证据时视觉项是 `NOT_RUN`，不能写 PASS。文字成品先 OCR 提取，再人工逐字核对；纯提示词阶段只能检查原文已正确编入，不能冒称 OCR 完成。

```bash
python3 scripts/validate_production_contract.py production-contract.json
python3 scripts/validate_production_contract.py revision.json --baseline production-contract.json
```

校验器无第三方依赖，校验本 Schema 所用结构、引用、硬锁覆盖、空间有向循环和状态证据；不验证自然语言真假、摄影物理、真实授权、官方能力有效性或图像质量。`--baseline` 检查旧硬锁定义及其值未漂移。用户明确修改硬锁时创建新合同 ID，在来源中保存修改依据，不能假装旧基线仍通过。

回放保留合同/编译器/适配器/语义片段版本、原始提示词、模型精确 ID、接口、参考文件哈希及实际参数；seed 仅在接口提供时记录。回放指重放配置，不能承诺闭源后端像素复现。

发布或迭代本流程时使用 [合同与叙事行为用例](../tests/production-contract-forward-cases.md)，分开记录自动校验、Agent 成稿评价与真实图像实验。
