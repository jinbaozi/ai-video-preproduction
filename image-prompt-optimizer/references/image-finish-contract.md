# 光色、景深、真实感与照片规格

用于包含配色、逆光、真实感、尺寸、清晰度或去噪要求的合同。复用 [布光与色彩](lighting-and-color.md)、[自然观看](natural-viewing-realism.md) 和 [图片质量](chatgpt-image-quality.md)，不把所有条目堆进每条正文。

## 因果一致的画面

- 主体、场景和镜头先成立，再调光色与细节。脸/手/产品结构错误属于结构问题，增加毛孔、锐度或胶片颗粒不能修复。
- 配色分主体固有色、照明色偏和最终调色。指定红衣不等于整幅染红；肤色/产品品牌色若为硬项应保护，局部环境反射可有轻微影响。描述主色/辅色/强调色及面积层级，不强制每幅三色或固定比例。
- 景深说明焦点目标、前后距离层次、哪些对象必须可读、背景虚化程度。多人跨深度全清晰与极浅景深可能冲突；可调整站位、光圈意图或特殊成像方式，但不能静默改硬要求。眼睛不可见时不强求双眼锐利。
- 逆光先给光源相对相机/主体位置与高低，再给轮廓出现部位、主体面部曝光/补光、背景高光保护和材质透光性。剪影是合法意图；既要求清晰面部又强逆光时说明曝光与环境反射/补光，不默认多加一个太阳或光晕。眩光不等于逆光，发丝轮廓光不是所有材质必有。
- 细节按景别和媒介选择：近景皮肤层次、衣料织纹、金属反射、接触褶皱；远景轮廓、层次和大材质。低光不应同时承诺完全无噪与每根毛发锐利；允许物理合理的模糊或遮挡。

## 去噪合同

先判断用户要去除的对象：异常彩色噪点、亮度噪声、压缩块、条带、渲染碎片、锐化白边；再区分用户要保留的胶片颗粒、皮肤毛孔/痣/雀斑、纤维、纸纹、笔触和有意虚焦。仅有文字且无原图时将缺陷标为用户报告，不能声称已经看到。

正文采用“去除对象 + 作用区域 + 保留项 + 失败条件”。例如：仅降低阴影中的异常彩色散点，保留原肤色、年龄、妆容、皮肤标记、细小明暗起伏、发丝及原景深；不得把皮肤变成平滑塑料，不额外补颗粒、色差或光泄漏。若用户选择无颗粒数字照片，则不擅自保留新增胶片感。

验收按整图、目标显示尺寸和可获得的原像素局部分别检查；缩略图不能证明去噪细节保留。降噪后仍糊不等于需要全图锐化；核对对焦、运动模糊、重采样和原始分辨率。没有实际生成/编辑工具执行时只能交付去噪指令，不能写“已去噪”。

## 尺寸合同

分别记录：`aspect_ratio`（画幅）、`requested_pixels`（用户目标）、`delivered_pixels`（读取成品后才填）、`native_resolution`（unknown/verified/derivative）、裁切安全区、文件格式与用途。纸张物理尺寸和 PPI 仅用于印刷换算：像素 = 英寸 × PPI；修改 DPI 元数据不增加像素细节。

照片宽高、横竖方向与画幅应一致；不要自动把 4K 当成 4096×4096、把竖版尺寸写成横版。要求严格 2160×3840 时明确宽×高；接口不支持就记录 BLOCKED 或用户接受的生成后裁切/放大路径，不能把放大交付称原生。调整画幅时先查裁切会否截掉头脚、道具或精确文字。

API 支持与尺寸合法性要按精确模型/端点核验。既有 `validate_gpt_image_2_size.py` 只用于其已声明的 GPT-Image-2 规则快照，不可套用到 GPT Image 2.5、Gemini、网页端或其他后端。ChatGPT 非 API 提示词可描述画幅目标，不能把 size、quality、seed 伪装成已执行的界面控制。
