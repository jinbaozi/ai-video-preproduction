# GPT-Image-2 4K 与尺寸校验

用户要求 4K、自定义像素、横竖版转换、图生图高分辨率或“原生 4K”时完整读取。能力核验日期：2026-08-20。尺寸是接口参数和最终文件属性，不是靠在主提示词中加入“4K／8K／超高清”获得的风格效果。

## 1. 界面路由

| 界面 | 安全处理 |
| --- | --- |
| ChatGPT Images／内置图像工具 | 用横向／竖向、构图比例和用途表达意图；只有界面明确暴露像素控制且生成后可核验文件尺寸时，才声称精确 4K。 |
| Image API generations | 当前指南和生成请求参数支持满足约束的 `WIDTHxHEIGHT`；`3840x2160` 与 `2160x3840` 是官方列出的实验性 4K 尺寸。 |
| Image API edits／参考图工作流 | 当前 Python／CLI edits 请求参数明确支持 `gpt-image-2` 合法 `WIDTHxHEIGHT`，可直接请求横向或竖向 4K；仍须标记实验性并核验下载文件像素。 |
| Responses API 图像工具 | 当前指南支持灵活尺寸；给具体代码前核对本次工具 schema 和主模型写法，不要把 Image API 端点字段塞进主模型。 |

Image API 图生图需要 4K 时，先完成编辑合同，再把经校验的尺寸放在参数区。若某个过期 SDK 类型只接受固定尺寸，先核对并更新到当前支持 `gpt-image-2` 灵活尺寸的 SDK／调用方式；只有实际服务仍拒绝目标值时才降级到当前可用尺寸并后期放大，且必须标为“后期放大”，不能冒充模型直接输出的 4K。

## 2. 当前尺寸约束

对 `WIDTHxHEIGHT` 逐项验证：

1. 宽和高都是正整数且为 16 的倍数。
2. 最长边不超过 3840。
3. 长边／短边不超过 3:1。
4. 总像素在 655,360—8,294,400 之间，含边界。
5. 总像素严格大于 3,686,400 时标记为实验性，不把“合法”误写成“稳定”。

优先运行 `python3 scripts/validate_gpt_image_2_size.py <WIDTHxHEIGHT>`，避免心算漏掉像素上限。当前 API 指南与生成 API 参考明确列出 3840 边界和 4K 尺寸；Cookbook 一处仍写“最长边小于 3840”，按更高优先级的当前指南／API 参考采用 `<= 3840`，同时保留冲突记录。

## 3. 常用尺寸与状态

| 目标 | 尺寸 | 状态与说明 |
| --- | --- | --- |
| 通用方图 | `1024x1024` | 合法、非实验性 |
| 常用横图 | `1536x1024` | 合法、非实验性 |
| 常用竖图 | `1024x1536` | 合法、非实验性 |
| 16:9 可靠性边界 | `2560x1440` | 合法；总像素正好等于实验性阈值，不标实验性 |
| 4K UHD 横图 | `3840x2160` | 合法；总像素正好达到上限，实验性 |
| 4K UHD 竖图 | `2160x3840` | 合法；总像素正好达到上限，实验性 |
| 最大合法方图 | `2880x2880` | 合法、实验性；不是 4K UHD 方图 |
| 1080p 竖图 | `1080x1920` | 非法；1080 不是 16 的倍数。精确 9:16 可用 `1152x2048` 后缩放，或接受 `1088x1920` 的轻微比例变化 |
| DCI 4K 横图 | `4096x2160` | 非法；最长边超过 3840 |
| “4K 方图” | `3840x3840` | 非法；总像素超过上限 |

不要把“4K”理解为任意边长 4000 左右，也不要把像素数写入摄影叙述。先从交付比例选择合法尺寸，再单独列入生成参数。

## 4. 4K 提示词与工作流

主提示词只描述在最终观看尺度上需要保留的可见结构，例如产品边缘、包装小标签、织物纹理、发丝边缘、图表节点和文字层级；删除“4K、8K、超高分辨率、极致细节、杰作”等无法替代参数或验收标准的词。

推荐两阶段工作流：

1. 用 `quality: low` 和较小合法尺寸比较构图、主体数量、版式与文字层级。
2. 锁定已通过的提示词和不变量，再以目标尺寸比较 `medium`／`high`；近景身份、密集文字、信息图、产品细节和高分辨率成品以硬门选择，不宣称 `high` 必然更好。
3. 下载后读取实际文件像素；只有实际尺寸等于目标且未经过外部放大，才可称“模型直接输出的 4K”。
4. 逐项复核主体、文字、局部编辑范围、结构、材质和边缘；大图合法但实验性，结果可能比 2560×1440 更不稳定。

## 5. 失败回退

- 尺寸非法：明确指出违反哪条约束，并给出最接近用途的合法方案，不静默改值。
- 旧 SDK／客户端拒绝合法 4K：先核对当前 edits 请求参数和 SDK 版本；实际服务仍拒绝时再降级到可用尺寸并标注后期放大。
- 4K 结果结构漂移：回到已通过的小尺寸构图，保持提示词不变，只改变尺寸／质量做对照。
- 精确文字在 4K 仍错误：只修文字并锁定版式，OCR／人工校对；不要继续堆“超清”词。
