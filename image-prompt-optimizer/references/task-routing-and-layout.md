# 任务路由与结构化视觉

当任务不限于人物摄影，或涉及产品、插画、海报、社媒、信息图、UI、网页模型、多面板叙事、参考图生成、遮罩编辑或多图合成时完整读取。先判断操作模式，再选择资产类型；不要用一套人像摄影清单覆盖所有图像任务。

## 1. 操作模式

| 模式 | 判定 | 提示词核心 | 主要验收 |
| --- | --- | --- | --- |
| 文生图 | 没有输入图，创建新画面 | 用途、场景、主体、关键细节、构图、视觉语言、约束 | 主体、构图、文字、禁用项 |
| 参考图引导的新图 | 输入图只提供身份、物件、风格、色彩或构图方向，输出不是某张基图的局部修改 | 逐图编号和单一主角色；说明哪些特征迁移到新画面 | 来源绑定、特征保真、新构图是否成立 |
| 整体编辑 | 以图 1 为基图，允许改变场景、风格、天气或多个明确属性 | 编辑对象、允许改动、不变量、融合要求 | 编辑范围、基图保留、全局一致性 |
| 遮罩／局部修补 | 只修改指定区域或对象 | 遮罩对象、唯一改动、边界内外不变量、接缝要求 | 局部性、边缘、遮挡、纹理、阴影 |
| 多图合成 | 从多张图取元素放入指定基图或新画面 | 每张图角色、元素来源、目标位置、尺度／透视／光色／接触匹配 | 无错绑、无重复、无漂浮、融合自然 |
| 连续修订 | 已有结果，只修一处或一组不可分割的因果 | 最小 Prompt Delta；重复关键不变量 | 目标问题改善、无编辑溢出 |

“上传了图片”不自动等于编辑：若图片只负责视觉方向而用户要求全新构图，路由为参考图引导的新图；若用户说“只改图 1 的某处”，路由为编辑。

## 2. 通用输入骨架

按需提取：交付物与用途；目标受众或阅读距离；操作模式；主体与主要事件或信息主线；场景；视觉媒介；构图、视点和留白；光线、色彩与材质；精确文字；必须出现／不得出现；参考图角色；模型、界面、画幅和尺寸。缺失项只有在会改变主体、叙事、版式、权利或模型参数时才追问。

新生成稳定顺序：`用途与交付物 → 场景／背景 → 主体／事件 → 关键细节 → 构图／版式 → 光线／色彩／材质 → 精确文字 → 约束`。

编辑稳定顺序：`编辑操作 → 输入图角色 → 只允许改变 → 必须保持 → 融合与边界 → 验收`。

简单任务写 1—3 个完整句子；复杂画面用短标签换行。不要为了结构完整而填入不可见、未要求或无验收价值的字段。

## 3. 资产类型路由

| 资产类型 | 必须说清 | 常见硬门 |
| --- | --- | --- |
| 写实照片／人物 | 动作时刻、景别、机位、主光、可见纹理 | 身份、身体结构、注视、接触、摄影因果 |
| 产品／电商／包装 | 产品几何、朝向、标签可见性、表面材质、使用场景 | 轮廓和部件不漂移、颜色准确、无额外产品／标志 |
| 插画／概念图 | 媒介、线条或笔触、形状语言、色块与空间处理 | 风格内部一致、主体可读、无无意写实或媒介混杂 |
| 海报／社媒／营销图 | 渠道、阅读距离、标题层级、主体与文案安全区 | 交付类型正确、文案准确、层级清楚、无额外文字 |
| 信息图／图解 | 信息层级、节点／步骤数量、阅读顺序、连接关系 | 数量、标签、关系、图例和文字逐项正确 |
| UI／网页模型 | 设备或画布、屏幕类型、区块、状态、主操作和真实控件 | 页面类型、必需区块、CTA 层级、可读文字、无占位乱码 |
| 多面板／分镜／漫画 | 面板数量、网格、阅读顺序、每格事件和连续性锚点 | 不漏格、不合并、角色与道具跨格一致、对白归属正确 |

信息图、UI 和营销图先把“正确交付物、必需组件、精确文字”设为通过／失败硬门，再评估层级、风格和美观；不能用平均审美分掩盖文字或结构错误。生产关键文字须 OCR／人工逐字复核，密集排版最终用设计工具精修。

## 4. 参考图绑定

- 为每张图分配明确职责（可有多个已声明职责）：待编辑基图、身份、产品、服装、姿态、构图、色彩、材质或视觉特征。基图可承载一组显式不变量。
- 写成“从图 2 取产品，把它放到图 1 右侧台面”，不要写“融合附件风格”。
- 风格参考只提取可观察特征，如线条粗细、色块、光比、颗粒和空间密度；不要声称复制作者身份。
- 多图冲突时按用户优先级解决；没有优先级且冲突会改变结果时先追问。

## 5. 最小验收

先检查硬门：交付物类型、主体／产品／身份、数量与空间关系、精确文字、允许改动和不变量。硬门通过后再检查构图层级、光色、材质、风格一致性和审美。已有结果的下一轮只改最高优先级失败；除非多个问题属于同一不可分割因果组，不要整段重写。


## 数量与叙事补充

分别确定输出图片数、面板数和主体数；单图不等于单人或单面板。唯一事件是简单叙事的默认组织方式，多事件街景、群像或漫画以层级和阅读顺序组织。多主体按 multi-subject-and-interaction.md 绑定；复杂构图按 composition-and-scene.md 选择。参考图可提供多个明确职责，不无条件复制其余内容。
