# 自然观看前向用例

发布“自然观看现实感”更新前，由未参与编写的独立执行者直接调用本技能完成以下请求。执行者只看到用户请求和技能，不获得诊断结论；无需实际生成图片。

## 执行规则

1. 每个用例使用新上下文，完整读取技能按需路由到的参考文件。
2. 评价提示词是否把“人眼感”转成可见、可验收的摄影因果，不评价随机出图结果。
3. 不要求执行者机械写出全部五张因果图；简单任务仍须简洁。
4. 任一概念边界、物理因果、模型语法或单变量修订阻断项失败，修订后使用原始输入重跑。

## 用例矩阵

| 编号 | 用户请求 | 必须观察到 | 禁止出现 |
| --- | --- | --- | --- |
| NV-01 | “GPT-Image-2：帅气年轻男性坐在明亮客厅沙发上横握手机玩手游，像肉眼看到一样自然，不要 AI 感。” | 1—3 句且不以分号堆成检查表；只保留 2—4 组最高风险因果，至少覆盖单一投影中心与可信视点／连续景深、同一屏幕注视点与距离相称的轻微会聚／双手握持、朝向使用者的屏幕与相机三分之四观察关系；光线或生活痕迹只在用户／图像依据成立时择要加入 | 50mm 等于人眼；200° 鱼眼；无限 HDR；全画面同锐；正面人脸和完整屏幕同时正对镜头；表面响应与材质／光线不符的贴图屏幕；无菌图库布景 |
| NV-02 | “第一人称看向桌上的咖啡和打开的书，要求真实人眼视角。” | 明确观察者眼位、头部方向、可见手臂范围和桌面尺度；单一静态投影；用注意层级而非径向模糊 | 鱼眼、黑色暗角、固定周边涂抹、声称复刻双眼调焦或扫视 |
| NV-03 | “窗外很亮、室内很暗，但要像人眼一样全部看清。” | 解释静态图不能复刻跨时间适应；选择曝光锚；平滑高光滚降、真实黑位和选择性暗部细节 | 固定动态范围档数；窗外、肤色和深阴影全部同亮；HDR 光晕或全局提灰 |
| NV-04 | “人物低头看近处手机，但生成结果两眼像在看不同地方。” | 只校正同一物理注视点、与距离相称的双眼会聚、眼睑和必要的轻微头部角度；若屏幕朝向使人物实际看不到内容，只联动最小屏幕倾角；重述人物身份、表情强度、手势、手机位置、机位和构图不变 | 重画整张脸；添加无来源强眼神光；夸张斗鸡眼；为迎合镜头把屏幕背离使用者 |
| NV-05 | “只修手机屏幕像后贴上去的问题，其他完全不变。” | 有图时按确定证据判断平面透视、内容贴合、玻璃反射或亮度；无图时请求原图，或在用户要求直接成稿时明示一个单一保守假设；锁定手势、人物、机位、焦点、环境光和调色 | 假装看过未提供图片；一轮同时重做 UI、反射、手部、灯光和构图；含糊写“更真实”；屏幕霓虹照亮白天脸部 |
| NV-06 | “人、手机、耳机、水杯都很清楚，但沙发和同一位置突然糊掉，只修景深。” | 仅重建相对焦平面连续变化的离焦关系；同深度物体相近；保持主体、物件位置、机位、光线和颜色 | 用语义类别决定清晰度；写成离相机越远越糊；移动或删除物件；重画人物；增加抠图边缘 |
| NV-07 | “日光窗在左、暖色落地灯在右，人物肤色必须自然。” | 明确主光与肤色曝光／白平衡锚；保留暖灯局部影响、冷暖互反射和一致阴影；屏幕若存在则服从环境亮度 | 所有光源强制中和；暖灯从错误方向塑造阴影；皮肤同时被冷蓝和橙色重染 |
| NV-08 | “自然居家抓拍，但画面总像精心摆好的广告图库。” | 只增加最少且与活动相关的克制使用痕迹或轻微不对称，降低无关道具视觉权重；保持整洁与用途 | 机械规定道具数量；堆脏污、垃圾和随机缺陷；倾斜地平线；用噪点和失焦冒充抓拍 |
| NV-09 | “审查这张人物持手机的参考图，指出不自然处并优化提示词；不要把正常现象误判为缺陷。” | 先以整图检查视点、比例、动作与光线，分辨率足够时再以原尺寸局部检查眼睛、手、接触边缘、屏幕与反射；按“确定问题／疑似问题／可合理解释／分辨率不足”分级；把高置信失败转成最小范围修订 | 凭空宣称多指、断肢或透视崩坏；把合理窗户溢出、自然遮挡或运动瞬间一律判成错误；把不可见细节假装成已确认；一次重画整图 |
| NV-10 | “正面看清人物玩手机的表情，同时完整正面看清手机屏幕，必须像自然抓拍。” | 明确单一普通投影视点不能同时提供正面完整人脸和正面完整屏幕；先追问或确定二者优先级；只有接受三分之四面部、斜向屏幕或局部内容时，才使用靠近视线轴的高斜／肩侧／越肩机位兼顾 | 屏幕无故正对相机而人物从明显侧面注视；把脸与屏幕拼成两个投影视点；暗示换个普通机位就能让两者同时正面完整可见 |
| NV-11 | “只有一张宽 480 像素的聊天缩略图，判断人物握手机的手是不是多了一根手指，并给修复提示词。” | 明确微小手指结构分辨率不足，不把缩略图当原图；请求原图／局部裁切，或只列低置信观察点且暂不下多指结论 | 把压缩块、遮挡或运动边缘断言成多指；引用不存在的像素证据；在未确认前重画整只手 |
| NV-12 | “审查清晰原图中人物低头看近处手机的注视：一只虹膜明显朝手机转动，另一只近乎居中。不要把偏侧目标或头部透视造成的正常不对称误判为斜视。” | 先定位同一屏幕点，再逐眼比较虹膜相对眼角／眼睑的位置、头部姿态和手机三维位置；只有图像证据足以排除偏侧目标、头部透视与遮挡解释时才列为高置信注视异常，否则列为疑似或分辨率不足；确认异常后才给注视最小因果组修订 | 仅凭“一眼近乎居中”的文字就断言异常；用眼神光位置代替注视判断；忽略正常不对称解释；在未确认前重画双眼 |

## 通过门槛

- 十二个用例均先正确路由到自然摄影、明确要求的主观化注视效果或双目／立体／VR；普通单幅图和仅说“像肉眼看到”时默认自然摄影。
- 十二个用例均不把人眼当作固定参数相机。
- NV-01、NV-05、NV-06 能分别处理新生成、单材质修订和单光学修订，不互相污染。
- NV-03、NV-07 的曝光、白平衡与混合光有明确优先级，未出现 HDR 或全中和捷径。
- NV-04 的两眼、头颈和目标几何一致，但不强迫像素级相同眼神光。
- NV-09 区分可见证据、合理解释与分辨率不足，不为迎合用户而虚构严重缺陷。
- NV-10 的注视点、屏幕法线与相机位置属于同一可实现视点；存在取舍时不静默制造多视点拼贴。
- NV-11 不在低分辨率缩略图上声称确认手指数量或微小结构错误。
- NV-12 逐眼验证视轴是否落在同一物理目标，并在排除偏侧目标、头部透视与分辨率问题后才升级置信度。
- 所有简单成稿保持克制；复杂因果用于内部检查或短标签分段，不整表输出。
