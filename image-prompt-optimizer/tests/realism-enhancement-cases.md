# 真实人像增强行为用例

发布或回归真实人像增强时使用。下面是待执行用例及验收标准，不是已通过记录。结构检查不替代行为验证，行为验证不替代生图实验。独立执行时只给请求与技能路径，不提供本表的预期列。

| ID | 原始请求 | 预期行为 |
| --- | --- | --- |
| R01 | 写一条窗边真实人像提示词，只要三句话。 | 短提示，允许零数值，不输出完整 EXIF 或整张档案 |
| R02 | 商业头像，修饰到没有痘印，保留皮肤纹理。 | 容许修饰和纹理共存，不阻断、不添加污渍 |
| R03 | 对称构图的真实抓拍，她刚回应镜头。 | 保留对称和直视，不误判硬冲突 |
| R04 | 全身穿搭，想有毛孔真实感。 | 解释观看尺度，保留肤质意图，不制造满身微纹理 |
| R05 | 为参考人物写局部编辑词，只修皮肤油亮。 | 锁身份、年龄、妆面和光位，不新增痣或皱纹 |
| R06 | 雨夜35mm，1/30秒直闪，人脸清楚，背景拖影。 | 解释闪光主导与环境重影，不只凭快门判失败 |
| R07 | 三个人穿同款制服，正式合影。 | 保留统一造型、属性归属和共同成像，不强制差异化 |
| R08 | 戴不透明墨镜的半身真实肖像。 | 不要求可见虹膜或眼神光，用可见部位表达状态 |
| R09 | 写编辑指令：修皮肤高光、把杯子改蓝、删背景路人，其余不变。 | 全部保留兼容修改，不强制只完成一项 |
| R10 | 没有原图，只有用户说缩略图里手像多了一根，帮诊断。 | 不假装看图；请求原图或明示假设，不宣称多指 |
| R11 | ChatGPT网页生成人像，要求原生4K。 | 区分目标与可控参数；未读原文件不宣称像素通过 |
| R12 | 水墨插画人物，只优化笔触和留白。 | 不注入毛孔、光圈、纪实摄影规则 |
| R13 | 优化自然人像提示词：左前方大窗柔光，要立体，别变成硬光。 | 保留柔侧光，以方向与明暗塑形，不把柔光等同均匀平光 |
| R14 | “机顶直闪一定更立体、更真人”对吗？给我一条机顶直闪快照提示词。 | 条件化纠正绝对结论，仍保留指定机顶直闪；说明人物与背景曝光、阴影，不偷换离机侧闪 |
| R15 | 给原参考人物的修订词加入“原图模式、破坏性词”去 AI 味，但年龄、皮肤标记、妆面都不能变。 | 将标签转为低修饰或局部纹理目标，无图时明示保守假设，不伪造模式／RAW 输出；不添加雀斑、年龄特征、未指定的颗粒／色差或通用缺陷清单 |
| R16 | 分别写两条风格变体：复古胶片边缘漏光、现代镜头逆光眩光；脸要清楚。 | 两种效果分别表述成因、落点和强度，保护主体；不将漏光与眩光视为同义词 |
| R17 | 运动抓拍提示词：手臂和发梢略有方向性模糊，脸仍可辨，别把背景全部糊掉。 | 模糊绑定动作与区域，保持用户清晰区，不机械要求全图同锐或全图模糊 |
| R18 | 用本技能设计实验，比较皮肤、光线、镜头瑕疵三招和相机数值；我用 ChatGPT，没有 seed。 | 复用 A/B/C，三类描述单独消融，等量多样本盲评含商业场景；基线与增量不互斥，光源条件共享，C 只加数值而不新增摄影效果；无身份参照不声称同一人，标为探索性，不生图或宣称固定增益 |
| R19 | 没有原图，只听说双眼高光不同、脸很光滑，能确定是 AI 吗？ | 不判来源或报概率，说明光照／视角／修饰等替代解释和证据不足 |

执行记录保存于任务工作区，记录请求、实际输出、判定和限制；不要将完成状态写成本文件永久事实。至少覆盖一次新生成、一次多项编辑与一次证据不足的任务。只有需要验证图像效果且已获授权时，才转入生成流程。
