# 分镜最小阶段：核心合同

## 输入与责任

读取当前范围的DirectorIR/ArtIR、真实资产与硬约束；原文、信息顺序、服装、持物、场景关系不能在拆镜中重置。

每镜保留目的、景别、机位、主要动作/反应、声音、时长、起止状态及切点；重要接触动作须可读且有因果。主体与相机轨迹分开，动作不可在不合格切点断开。

## 四步闭环

1. 验证来源、范围、原生输入和锁定项；缺真实媒体/权限/能力时保留阻塞，不伪造记录。
2. 执行自动方法路由。完整任务使用已经嵌入的task.craft；独立创作按当前目标选择登记方法。当前场/镜细化，主语法保持稳定，不覆盖用户要求。
3. 在授权范围创作或复用一个权威原生结果。只补影响叙事、可见画面、模型输入或验收的字段；确定性校验由脚本承担，语义与视觉检查由宿主承担。
4. 检查硬约束、采用证据和交接。失败返回原责任字段/阶段；普通选择由宿主定稿。通过后提交现有结果与审计，不另写重复的计划/上下文/方法清单。

## 原生交付与命令

交付StoryboardIR、必要关键帧和控制需求。简单镜头不新增控制资产；分镜网格用于审阅，不假定任意视频入口能直接消费整张网格。

```sh
python scripts/craft_router.py "当前镜头" --role storyboard
python scripts/storyboard.py inspect STORYBOARD.json
```

命令在当前技能目录执行，示例不代表已执行。仅在相应原生结果需要时调用验证器，不让用户填写项目协议。已有上游时继承其来源与版本；独立结果不是自动获得完整流水线验收。

## 自动路由与审计

完整任务先读取最小任务视图，不重复打开其审计信封、整库注册表或来源目录。名家是项目归纳的方法参考，不是原话或质量保证；指明采用方法对应的实际内容和可观察结果。没有指定名家也保持自动路由。

采用证据相同时可分组列rule_ids，逐项覆盖规则不减少；不同场景/字段/结论不得为了省字合并。程序生成指纹与读取/校验回执，宿主不手填哈希、不自动宣称应用成功。未知、冲突和不适用必须有范围与理由。

最小审计保留输入/输出指纹、所选方法、采用位置、硬约束检查、结论与阻塞；真实生成与画质状态单列。问题只修受影响的字段和下游，不重写上游已接受内容。相同成功结果幂等；外部状态UNKNOWN先回收，禁止盲目重试。

## 按需深入

仅遇模型专属语法、复杂空间/接触、来源冲突或验证器指出的字段问题时展开[完整执行参考](detailed-execution.md)的对应章节；[资料索引](resource-index.md)保留全部方法、人物与场景路径；[专业路由合同](craft-routing.md)解释来源、主语法和采用证据。

## 独立采用证据绑定

在独立运行中，宿主先保存路由plan与原生产物，再写实际采用发现。以下命令只填充指纹并校验，不创作发现；支持显式rule_ids分组。

```sh
python scripts/craft_router.py --plan /tmp/plan.json --review /tmp/review.json --artifact /tmp/native.json
```
