# 制作合同

本合同是创作和执行协作协议，不是代拟法律合同。机器结构位于 `schemas/production-contract.schema.json`，
嵌入 DirectorIR；人类可读版本由编译器生成。一个要求应能回答“来自哪里、怎样实现、怎样判定完成”。

## 必填关系

`clause.id → source_refs → DirectorIR JSON Pointer → check_ids → ExecutionIR 路径/损失 → QA evidence`。

每条 clause 写明确 requirement、hard/soft、来源ID、关联字段、验收ID和变更策略。
`allowed_channels` 明确允许通过 native、lexical、natural_language、reference、post、review 中哪些渠道实现。
原生配音不可替代时，声音条款用精确 `/shots/N/dialogue` 路径并只允许 `native`；可后期配音则允许 `post`。
避免把不同渠道要求写在一个笼统父路径里，按需求拆成可判定条款。例子的全渠道集合表示允许有记录的适配，实际项目应按要求收窄。
每条 check 写门禁、范围、方法、可观察判据、证据要求、责任角色和是否阻塞。
“电影感强”不能作为唯一判据；写“关键物在显露前不可见，显露后观众能指出位置”。

来源要有 URI/文件、定位、具体主张和核验等级。社区经验可支持创作方法，不能作为平台API字段的唯一证据。
用户指定与 Canon 优先；新创作补充独立登记，不能反写为原著事实。

## 约束优先级

1. 用户不可协商要求及事实/身份资产。
2. 叙事信息顺序、物理与空间连续性、必要证据。
3. 目标入口真实能力、素材和执行条件。
4. 风格偏好与实现便利。

相冲突时记录具体字段与来源。平台无法满足硬要求，不等于硬要求自动变成软要求。
硬要求变更须产生新合同版本并保留明确决定；软项豁免需理由与授权来源。
脚本拒绝对硬要求直接 waive。用户已给过的决定可引用，不要求重复批准。

## 执行授权与预算

合同记录 plan_only/authorized_execution、授权记录、预算金额/币种、每任务最大尝试数、停止条件。
这些是上层执行器必须读取的约束；本包离线脚本不验证账户、不估算未取得的价格、不消耗额度。
进入外部执行前，把实际报价和剩余预算关联到任务；失败达到上限或价格/入口发生重大变化即暂停依赖执行。
单纯写 `authorized_execution` 不是授权证明，必须能回查已有用户决定。

## 完成与状态

- `STATIC_VALID`：IR结构和本版语义规则通过。
- `PLANNED`：静态编译计划已形成，无提交行为。
- `BLOCKED`：缺失具体资源/能力/证据，回执仍可交付审阅。
- `ACCEPTED_RECORDED`：证据文件、哈希、记录和上游版本对应，阻塞验收项均被记录为通过。

最后一个状态不等于脚本亲自观看了视频。视觉/听觉判据由记录中的审片者负责。
没有实际视频时，G3/G4必须 NOT_RUN；不能把“正文写了保持一致”记成“画面已经一致”。

## 变更与失效

身份图 → 相关关键帧、生成任务和Take；单镜头动作/光向 → 当前镜头与关联接点；
台词 → 配音、口型、字幕、相关时间锚点；字幕字体 → 字幕与最终渲染，不重生成角色视频。
本版脚本用整个IR/ExecutionIR哈希使旧QA失效，保守地拒绝复用旧签收。
细粒度复用由上层依赖图决定：提供旧证据、差异和明确新关联后重建QA记录；本包未实现自动局部失效引擎。
