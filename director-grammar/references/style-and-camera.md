# 风格自适应与镜头表达

## 选择策略

硬约束优先：任务类型、用户禁用项、身份/场景事实、空间连续性、关键证据与入口能力。
然后按信息目标、情感载体和生成复杂度选择。`dg.py route` 的标签交集仅是可解释检索启发式。
命令输出选择、匹配标签、被硬约束拒绝项和备选；不宣称统计最优或成功率。

风格注册表包含12种方法。导演索引保留引用对话的华语10位/国外10位，作为检索入口，不保留排行榜结论。
姓名输入会展开为 style_id；姓名不会由编译器自动写入视频提示词。
未知导演不能静默替换，需从用户参考或可核验资料写临时方法并注明依据。

一个场景的主风格写在 `scenes[].style_id`，镜头写实际采用的 `technique_ids`。
辅助技法须说明维度，例如主风格为克制悬疑、声音采用先声后画。不是机械叠加多个导演整套外观。
用户要求混合风格时，可先明确每个来源负责哪个维度，再检查冲突；新增风格记录要包含来源、适用/避用条件和备选。

## 摄影机行为要产生意义

| 方法 | 问题 | 必须检查 |
|---|---|---|
| 固定观察 | 观众是否需要看完整过程 | 身体/道具全过程是否仍在画幅 |
| 推进 | 从何种关系转到什么反应 | 终点是否保留手、脸、证据；是否真实位移感 |
| 拉出 | 新增什么空间或人物关系 | 扩大的环境必须有已登记来源 |
| 摇摄 | 视线转到哪里 | 机位应基本固定，速度和落点明确 |
| 平移/跟移 | 怎样追踪人物或揭示关系 | 脚步、背景视差、屏幕方向一致 |
| 环绕 | 遮挡后的什么因新机位显露 | 主体视角、背景视差和轴线转换成立 |
| 升降 | 高度改变让什么关系可读 | 不能用纯仰俯摇替代承诺的位移 |
| 变焦 | 为何改变视角范围 | 不声称得到推轨的透视变化 |
| 转焦 | 哪个证据接替注意力 | 前后对象同框、距离/清晰度变化可读 |
| 手持 | 谁的感知或运动需要不稳定 | 晃动不遮盖必要动作，不拿抖动代替真实 |

人物移动、相机运动、镜头光学和剪辑是四种不同手段。用最少的手段实现镜头功能。
每次切镜头说明它增加的信息或重新分配的注意力；没有戏剧冲突的产品/教学镜头仍可因展示功能成立。

## 叙事与剪辑

显露、反应、结果分配给可见证据。信息差镜头的验收是“观众比角色先知道”，不是暗光或配乐听起来紧张。
时间结构用 story_order 与展示数组顺序分离；同一事件复看时注明来源与新增信息。
平行剪辑说明各线是否同时发生、靠什么汇合。J/L-cut、图形匹配、动作接点各有不同目的，不能统称转场。

技法记录的用途、前置条件、参数、不可改变项、失败、替代与验收见 `registries/techniques.json`。
其中条件和验收是本项目设计规则；目前不含真实平台批量评测数据。
