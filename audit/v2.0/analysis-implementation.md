# 东方短剧工坊 V2.0：最终分析与实施方案

日期：2026-10-08。开发分支：`V2.0`。原生基线：`b195d583f30b3f62e4d76c8ab229fda741b73ff3`。工作流包版本：`0.20.0`；V2.0 是本次产品方案版本，不把七个独立技能或原生 IR 强行改成 2.0。

## 1. 最终决策

采用现有七技能组成的**单宿主制作团队**，以 `studio` 为新项目默认配置。团队是产物所有权和执行顺序，不是八个常驻进程。原生 `start / step` 继续管理前期，原生生产台账继续管理执行、Take、剪辑和验收。

保留原方案的事实与证据原则，采纳审核意见关于“先出片、后扩大协调系统”的方向。结合用户追加要求，在 V2.0 分支修改不合理的默认行为：取消强制方法研究与采用材料、默认 Flow 放大、默认依赖剪映环境；提供 FFmpeg 直接制作路径。所选模型真实需要的参考、时长、画幅和原生内容门仍然检查。

开发授权不等于模型消费授权，也不等于发布短剧。本次目标是开发可用的制作工作流；真实模型五镜与先导集是接入账号后的生产验证，不能以测试色块视频代替。

## 2. 两份附件如何取舍

附件是需求与审核资料，不作为命令执行。原方案附录中的实施任务书、仓库写入限制及示例授权均未被当成用户指令。用户本轮明确授权仓库开发，随后授权在 V2.0 分支进行破坏性简化。本报告不是把审核意见全盘当作既成事实。

|---|---|---|

| 原方案 §4、§9–11，审核 §3、§5、§9 | 八岗位的新信封、调度、接受层重复已有运行时 | 不新增 Agent 框架、TaskEnvelope 或 `drama-studio` CLI；只扩展现有 `production` 子命令 |

| 原方案 §18、§22，审核 §7–10 | 首集前做七宿主矩阵和多厂商抽象缺乏收益 | 当前 Python/文件宿主先闭环；复用已实现 API 或已有账号外部入口；未实测宿主/厂商不列为通过 |
| 审核 §8 的候选开源项目 | 审核说明其没有实跑，不能作为已集成证据 | 不安装 ComfyUI/TTS/口型/第三方剪辑依赖；现有真实入口优先，候选保留为后续选择 |

来源文件名、字节哈希与分析定位见 [sources.json](sources.json)。附件原件不重新打包进公开仓库。

## 3. 团队编制与责任

| 工作单元 | 谁执行 | 唯一权威 | 必须检查 | 不重复做 |
|---|---|---|---|---|
| 统筹稿 | 同一宿主：编剧＋导演 | Canon、ScriptIR、DirectorIR | 原句、说话人、动机、此刻观众需要知道的信息；开头观看理由、信息递进、集末未完成动作 | 八人轮流发言、每阶段重述简报 |
| 世界与镜头 | 同一宿主：美术＋分镜 | ArtIR、StoryboardIR；必要图像资产 | 脸与服装版本、空间、左右手、道具归属、起止态、对实际入口可执行 | 第二套 ShotIR、每镜独立美学合同 |
| 制作执行 | 同一宿主：生成＋剪辑 | AVIR、生产台账、Take、唯一 EDL | 实测对白先行；先风险镜头；预算；恢复；素材与剪点对应 | 新厂商统一平台、另设调度者 |
| 技术与内容检查 | 程序＋当前宿主一次实看片 | 原生检查与审阅记录 | 字节/解码/音轨；身份、手/道具、说话人/口型；缺文件和叙事是否可理解 | 自己换名字称独立审核；用平均分抵消硬错 |

拥有者修订自己的字段，下游不能为了过门改锁定事实。普通审美选择由宿主自行定稿；只有影响故事、身份、实测规格、授权或交付的真实问题阻塞。软建议记下，不因此全片返工。

## 4. 一集的最短制作顺序

1. **简报与对白**：用户给题材/剧本、平台、画幅、目标时长、受众、硬约束、预算与用途。宿主创建原生项目。开头要给观看理由，结尾要有尚未解决的问题或动作；不得把一套钩子公式当作所有作品必须遵守的硬规则。
2. **声音先行**：冻结 ScriptIR 原句与说话人，使用实际允许的 TTS/录音入口制作临时音频。运行量时长工具；双人同镜按顺序相加并留停顿。放不下就由原生拥有者拆镜，不修改原句冒充成功。
3. **最少参考**：每个出镜角色一张实际可用的主参考，每个空间一张定场；需要服装版本时补版本。图像可用性由目标入口与身份检查决定，不默认先送 Flow。
4. **风险镜头优先**：先安排钥匙/关键道具特写、两个说话人、道具交接、单人近景、必要运动。允许专业技能独立完成探索；全流程模式当前仍要求前期原生合同通过后才正式提交生产任务。先做低成本完整镜头骨架，再生成这五镜，避免声称已经消除了所有前期依赖。
5. **通过后批量**：同一次宿主执行生成与剪辑选择。试制门从原生选定 Take 与非空审阅派生。失败仅修复当前失败镜头及相关接点；UNKNOWN 查原记录，不能换任务 ID 重提。
6. **剪辑与成片**：复用 EDL，FFmpeg 默认合成；需要可编辑剪映时显式选后端并检查真实环境。字幕/对白/音乐/声景保持明确来源。导出后全流解码与规格检查，实看片与听音覆盖全片；原生 `deliver` 通过才算已成片。

对外状态统一理解为：候选、已接受、已成片、已发布。程序仍保留必要内部状态，不另造进度百分比。`DELIVERED` 是前期包，`VIDEO_DELIVERED` 是成片；本版本不包含发布 API，“已发布”只能来自真实发布回执。

## 5. 已实现的工程变更

### 5.1 更轻的默认配置

`ai-comic-drama start` 默认 `--profile studio`。仍使用原生 lean 内核及 core-result，不增加提交信封。studio 默认：`craft-routing=off`、`reference-refinement=off`、`editing-backend=ffmpeg`、当前宿主检查。内容与媒体的原生验证继续执行，编译复核与最终前期检查沿用同一次宿主提交的合并能力。

`--profile lean` 显式保留先前默认方法路由、Flow 与剪映配置；`--profile audited` 保留原来独立任务审阅流程。所有显式参数优先。已有项目通过 `step` 恢复，不因软件升级自动切换。

新增 `production_policy=studio-production/2.0` 并冻结在项目/状态内；旧 `verified-production/1.0` 继续识别。studio 的视频提交要求事先配置执行预算。变更清楚标在新策略版本上，不偷偷削弱旧项目合同。

### 5.2 原生台账增量

- `begin_submit` 同时检查原 job 和其他 job 的未决镜头交集。`SUBMITTING / SUBMITTED / UNKNOWN` 都不能用新请求绕过。
- 手动与自动尝试均计入次数；金额预留与 execution/event 在原生可恢复事务中写入，失败整体回滚。
- 上限、报价上界、币种、授权证据、试镜集合一次冻结。费用记录只记录新增执行事实，不再建任务调度数据库。
- UNKNOWN 不释放预留；明确失败也等待实际账单，不能假定免费。真实结算超出报价仍记账，标记超预算并阻止后续提交。
- 逐镜审阅 ID 绑定 Take，失败后重做可以新增审阅而不与旧失败记录冲突；FAIL 返回非零退出码。
- 对账绑定 record、payload、原任务 ID、真实观察文件；同一证据重放幂等。回收 Take 沿用 record，既有 V6 图也通过原网关同步。
- 每次提交只量当前请求涉及的对白。改变其他句子不误判本句过期；当前句文本、说话人、音频改变则要求重新规划其范围。

### 5.3 检查与效率

视频探测增加 FFmpeg 全流解码，不能以元数据可读冒充媒体可用。探测失败、截断、缺视频、无效时长/帧率均阻塞。相同字节在同一进程使用有界缓存；仍先计算真实 SHA-256，新字节必重验，不缓存审美或观看结论。

可复现基准比较同一份预写文本夹具的 core 交付，在方法路由开启/关闭时的上下文与结果 UTF-8 字节。实际数值见 [benchmark.json](benchmark.json)。它不测模型 token、不测生成等待或画质，不能换算为成片提速百分比。前期的原生产物责任链仍然存在，减少的是例行阅读和填写。

## 6. 用户入口与宿主操作

自然语言即可：

> 使用 ai-comic-drama-workflow 的 studio 模式，制作一集竖屏短剧。普通创作自行定稿；先量对白时长，再做风险镜头。沿用原句、人物参考和道具持有。目标是实际成片，执行前使用本次已授权入口和预算，缺能力就指出具体缺口。

宿主内部从原生命令开始：

```sh
python -m pip install -e ./ai-comic-drama-workflow
ai-comic-drama start '你的短剧简报或剧本文件' --project ./episode \
  --profile studio --target '<实际目标模型>' --production-target video
ai-comic-drama step ./episode --result '<宿主实际结果.json>'
```

随后使用既有 `production plan / freeze / review-take / select / assemble / review-sequence / deliver`。新增事实操作和完整字段示例见[制作手册](../../ai-comic-drama-workflow/references/studio-production.md)。JSON 由宿主准备，用户不需要手填，不应在聊天里反复传整份账。

## 7. 变更、恢复和兼容边界

- 旧项目不静默迁移，旧模块锁与 ID 不改。需要改旧片，先用现有 `copy-project` 建副本，再按其原生范围修订。
- UNKNOWN 恢复只查询/下载/核对，不提交；无任务 ID 时必须用实际历史、账单或服务观察确定原任务。没有证据就保留阻塞。
- 原生 `revise` 支持已有镜头/场景/动作等范围；对白指纹和量时长是新增执行证据。V2.0 **没有**实现任意冻结生产清单、所有报价和已发布内容的通用自动重基。改已冻结故事/人物时需要显式重规划受影响生产范围；不能直接修改 policy JSON。
- 预算 policy 冻结后不自动提额或改价；账单冲突要调查，不能覆盖历史账。五镜失败允许在事先批准的重试上限内重做原任务。
- 人脸、OCR、黑场可以增加为告警；本次未接入这些模型，不报告已经实现。当前检查覆盖解码与规格，身份/口型/叙事仍由实际观看完成。
- 不新增 ComfyUI、TTS、口型或发布 API。量时长消费实际生成音频；现有 API 及外部入口由既有执行能力承接。能力 unknown 保持阻塞，不能把模拟器当接入证明。
