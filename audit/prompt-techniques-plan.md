## 架构与边界

1. **通用方法**：时间区间连续覆盖、每个节拍一个主要动作、起止状态交接、参考的继承/禁止继承边界、主体与摄影机运动分离、可见物理因果、声音归属、基于可观察缺陷的真实性。复用原生 AVIR 字段，不新增并行项目状态。
2. **任务模板**：从上游模板提炼不同任务需要的字段、结构与验收点。只加载当前匹配条目；不得覆盖用户/Canon/导演锁定，不把模板默认 15/30 秒当模型能力。
3. **模型专属层**：严格匹配 model/version/profile/mode；Seedance 2.0 与 2.5 分开，Agnes/Kling/H3 不接收 Seedance 附件语法、时长断言或模态能力。社区观察标明证据级别；具体能力仍由锁定注册表裁决。
4. **集成**：在现有工作流当前任务与 video-prompt-compiler 中接入方法选择/检查/交接；编译继续生成原生 artifact、requests、逐段提示词与引用映射。保留旧项目兼容、compact 输出和 autonomous-until-blocked。
5. **验证与发行**：新增模型隔离、未知能力 fail-closed、模板不改写锁定项、无时间缝隙、生产编译交接、确定性/独立安装测试。运行现有回归并重建七个发行包及内置包；验证 SHA256/manifest 一致。

## 采纳标准

- 原始帖子存在或案例标记 verified，不等于该技巧跨模型复现，更不等于本项目生成效果通过验收。
- 保留来源固定提交、原始路径与署名；不批量复制第三方图片/视频/人物提示词，不提升来源对素材的授权范围。
- 不为规避能力问题自动改模型、时长、台词或制作目标。
- 不新增例行审批；登录、权限、费用、缺失真实媒体和失败质量门仍是真实阻塞。
- 静态测试与离线生产交接通过不冒充真实模型生成或成片 QA。

## 实施顺序

读取固定源码与参考模板 → 整理有范围/证据的精简方法目录 → 集成真实编译/任务路径 → 对抗测试并修复 → 全量回归与确定性打包 → 提交 GitHub 并记录可核验结果。
