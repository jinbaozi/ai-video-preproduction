# 默认专业方法路由：设计与验收计划

基线：`cbe513ca4a36b3d6d50d823a02880af48fa20774`。本节先记录设计；实施和实测证据在完成后补充。目标不是保证模型生成大片，而是让没有点名名家的请求，也必须经历可追溯的专业方法选择、实现和验收。

## 根因与第一性原理

已有技能具备按任务读取、风格注册表和专业边界；导演/编剧的人名主要作为检索入口。仅说“按需读取”不保证宿主真正选取参考、执行方法或将其传到下游。电影质量来自对观众体验的具体控制，不来自人名数量、镜头复杂度或提示词中的大片形容词。

因而需要的不是第八个创作技能，也不是第二套内容 IR，而是贯穿原有角色任务的一条小型决策链：

`用户内容与锁定 → 当前创作问题 → 适配的专业方法及来源 → 本场/本镜实现 → 可观察检查 → 实际媒体复核`

## 实施约束

- 新创作默认启用；独立调用各专业技能也须执行。明确关闭时记录原因，不伪造“自动采用”。已有锁定项目不静默迁移。
- 宿主从内容提取语义与范围；确定性工具负责候选选择、来源解析、冲突检查和证据校验，不把关键词计数包装成语义模型。
- 各职责独立选择，项目有稳定的主方法；连续场景继承基线，只允许有理由的局部差异。一个职责保留一个主方法和少量互补方法，不进行名家大杂烩。
- 用户显式要求、Canon、角色身份、时代地域、连续性、信息揭示顺序和已锁定镜头优先。点名也不能越权改写。负面偏好必须过滤候选；冲突须有可见结果，不静默回退。
- 参考人名只作来源与解释：最终输出必须把方法翻译成因果、表演、空间、运镜、转场、光色、服化道或声音的具体规则。没有可靠资料时标明未核验，不能补造名家观点。
- 摄影/剪辑/声音方法仍由导演与分镜承担；服装/化妆/道具仍由美术承担。图片和视频编译只消费已批准规则，不重新发明风格。
- 渐进式披露：先小索引，再只读命中的方法/人物条目；不得默认把整个参考库塞进上下文。复用未变的读取证据。
- 决策证据必须绑定当前输入、注册表版本和结果，写明为什么选、怎样用、检查什么。选中不等于采用；静态采用不等于真实媒体通过。

## 计划验证

无名家输入、明确偏好、明确关闭、否定偏好、歧义/空输入、类型混合、教学不强加剧情、安静场面不强加炫技、场景继承、跨职责越权、失效来源、内容变更后的证据失效、最终正文仅堆人名等对抗用例。检查新入口确实调用路由，不只检查注册表可读。

在可运行环境执行新增回归及原有相关回归，重建七个安装包并验证内置模块一致性；如某项未执行，明确写 `NOT_RUN`，不借用历史 CI 成功。真实 LLM 创作、模型生成与成片审片不属于离线测试的已验证范围。

## 已实施

- 新 `start` 默认冻结 `craft-routing/1.0`，显式 `--craft-routing off` 才关闭；旧 init 和已有项目不迁移。保持原七职责、原生 IR 和 lean/audited 两种审阅模式。
- 宿主在 Canon RoleResult 中提交带原文/实际观察证据的语义特征；确定性路由检索原生注册表，选一个主语法及少量互补方法，人物是有来源的项目方法入口。没有语义特征的独立 CLI 仅做词法初筛并明确标记。
- 导演结果冻结按原生场景 ID 的下游语义特征和连续空间组。美术按场景路由，分镜按场景补充局部规则；同一连续空间禁止不同美术主语法；局部采用证据不能指到另一个场景。
- 自动生成的小型 `craft:selected-methods` 读取件包含选中的规则、人物方法、来源定位/哈希、适用依据和检查项；不向模型倾倒整库。共享源同步到独立 Skill，安装后不依赖仓库兄弟目录。
- 选中人物的方法也成为需要实际采用证据的规则，不止保存一个姓名。服装/发妆、道具状态、光色、转焦、转场等分别服从原所有者和可读性目的。
- 原生结果的 `craft_review` 必须覆盖选中/继承规则，并绑定实际字段、摘录、字符串哈希和可观察检查。主语法字段、人名和评审元数据不算实现；不能全标不适用。未通过门禁的导入文件不能假装已采用。
- 方法采用项跨编剧→导演→美术/分镜→编译复核传递。最终编译复核检查真实冻结 AVIR；图片/视频编译不重新选风格。实际媒体生成、付费、独立审阅和真实画质验收仍走原协议，没有新增生成调用。

## 本地验证记录

截至本次源代码提交前，新增 **55 项路由/证据/场景/入口测试 + 1 项文字包端到端测试通过**。端到端使用预写咖啡馆 fixture 和真实原生校验器，不 mock 接受门禁，覆盖 Canon、ScriptIR、DirectorIR、ArtIR、StoryboardIR、编译复核和文字包交付；最终复核保留四个创作职责的方法来源，`video_generated=false`。

四个专业模块原有测试合计 232 项：231 通过、1 项按原测试条件跳过。七个安装包重新构建；第二次构建所有发布文件逐字节相同；六个内置模块与独立包一致。四个独立创作 Skill 解包后单独运行路由 CLI 成功；在只解包总工作流、没有兄弟仓库目录的环境中，55 项路由测试通过。

另行启动了原有总工作流与视频编译器完整回归。上述数字不包含未完成项，最终以对应提交的 GitHub Actions 日志为准。发布验证器已补入新测试及独立 CLI 检查，新增 Professional craft routing CI 持续检查共享源、安装包字节与新回归。

对抗检查发现并修正了：普通“一个动作”被误当动作片、产品演示被英雄登场抢占、色彩标签抢占悬疑主目标、`非线性`被误当否定、主风格标签冒充采用证据、用上游采用项掩盖本职责全跳过等问题。测试绑定与作用域可以自动检查；自然语言的艺术质量、源理解正确性和实际观察真实性仍需宿主/独立审阅，不能伪称算法已证明。
