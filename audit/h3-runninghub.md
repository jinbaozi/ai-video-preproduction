# H3 / RunningHub 实施与对抗审查

日期：2026-09-29。基于 main `177a723c21bc0a9dbb8392d08a313582e56fffc3`；视频编译技能升至1.20.0，总工作流升至0.14.0。没有更换既有 Canon、AVIR、状态图或七个专业职责。

## 从第一性原理得到的边界

控制结果依赖四件不同的事：明确可观察意图、选对模型输入模式、把控制送到真实执行节点、回收媒体验证结果。写长提示词不能替代图连接，节点静态正确也不能替代媒体 QA。因此默认只产出宿主写作的 H3 提示词与离线节点计划，不把计划升级为成功生成。

官方 Context-IR 未开源且是托管服务；本项目复用官方公开提示词指南，另行提供官方请求草案/回执导入，不做兼容性冒称。Context Loop 属于社区节点包，按使用前提作为可选经验，不当作官方 Context-IR 或默认依赖。

## 改动

- `vpc.py h3` 按需加载 `h3_cli.py`、`h3_runtime.py`、`runninghub_h3.py`。新增基础/参考两个 RunningHub profile；旧模型行为保持，H3 分段修正局部 Shot 编号和切点格式。
- `inspect → plan` 读取 API 图与顺序敏感指纹，核对原生模式、正向采样路径、检查点家族、VAE、实际引用序列、帧格和显式种子；仅生成可审阅的标量 CAS 修改和副本，不重连节点。
- `lint` 检查字段、剪切、台词语言标签、引用和 Subject 定义；`context-request/import` 输出离线请求或待语义审阅候选，保留来源指纹，不污染冻结 AVIR。
- SKILL 主入口只增加简短路由；基础语法、参考语法、节点操作、官方服务和经验分开按需读取。总工作流仅在 H3 的 avir/compile-review/qa 阶段加入路由，不给其他模型和早期创作阶段增加文档负担。
- 发行包继续使用原确定性打包器，独立编译技能与总工作流内嵌副本必须一致；隔离包验证新增 H3 测试。

## 未验证 / 不自动化

没有用户实际 RunningHub API 工作流、账号执行回执或生成视频。附带 API 图是明确标注的合成夹具，包含占位媒体/节点且未配置完整解码保存，不是可运行模板。未验证账户、节点安装、GPU、真实权重、媒体内容、画质或提速比例；不调用付费模型。

原 AVIR `compile` 仍输出保真审阅视图，并非自动将所有源文本翻译成英文或所有音轨转换为 H3原生语法。专属英文正文由宿主依据锁定要求在冻结前制作，经 `lint/plan` 检查；冻结后重写必须走新候选和原语义复核，不绕过生产状态机。

RunningHub 自有 Context-IR 包装的具体请求/回执尚未核验，不猜测其字段。当前导入器仅接受明确的 MiniMax 官方格式，且仅能验证调用方文件之间的一致性，不能证明调用真实性。自定义节点超出已识别范围时停止自动改写。所有计划保留 `submitted=false` / `runnable=false` / `media_qa=NOT_RUN`。
