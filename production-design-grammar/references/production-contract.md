# 美术制作合同

这是制作协作协议，不是法律合同。与director-grammar采用相同五项可追溯原则，但只签美术范围。

`clause.id → source_refs → ArtIR JSON Pointer → execution task/channel → check_ids → 实际证据`。

## 五项必备

| 项目 | 必填内容 | 不合格示例 |
|---|---|---|
| 有来源 | URI/文件、定位、具体主张、provided/read/observed/inference/unverified | “大师风格”，无出处；推断标史实 |
| 有结构 | 稳定实体/资产/场景/镜头ID、版本、坐标、材料及状态 | 人物和背景混在一段泛描述 |
| 有约束 | hard/soft、不可改项、允许状态、适用镜头、变更策略 | 为平台便利把六柱改成大约几根 |
| 有执行路径 | prompt/reference/post/review之一、明确操作、参考依赖、责任与预算边界 | “后续处理”，无任务和方法 |
| 有验收条件 | 检查ID、G0–G4、方法、范围、可观察判据、证据与审核者 | “美、电影感、高级”是唯一标准 |

精确画内文字优先 `post`；身份与几何参考用 `reference` 并列真实参考ID。
`prompt` 只代表表达渠道，不保证生成结果满足。`review` 是明确联合设计审查步骤，不代替物理制作。
每条hard必须关联一个阻塞媒体验收项。合同JSON与可审阅Markdown由同一数据生成，避免两份事实源。

`paths` 应细到真正约束的字段，不能指向合同自身制造循环覆盖；`shot_ids=[]`代表项目全局。
含显露、事件或未来状态的要求必须限定相关镜头，防止进入前序提示词泄露剧情。
编译覆盖是显式字段/任务关联，不是自然语言等价证明；人仍需核对条款是否表达了用户原意。

## 门禁

- G0：来源、身份、版本、输入完整性；结构脚本通过不能冒充历史研究核验。
- G1：世界/空间/服化/道具设计与导演要求一致；包含人工布局与可读性审核。
- G2：每条要求有任务与参考；入口、槽位、素材等缺项记录阻塞。
- G3：实际图/镜头素材的身份、布局、材料、构图支持、表情可读性、接触和状态。
- G4：最终全片播放中的跨镜连续、反打关系、图形文字和风格继承。

静态程序返回 `STATIC_VALID`，编译返回 `PLANNED` 或 `BLOCKED`；二者均未提交。
QA记录核对通过返回 `ACCEPTED_RECORDED`，意为具名审核记录与字节证据完整，绝非代码理解了图像。
本包不会自动把G0–G2的人工条款标PASS；生成的全部QA条目都为NOT_RUN。

## 执行与变更

`execution`记录plan_only/authorized_execution、授权来源ID、预算/币种、尝试上限及停止条件。
已授权状态只是宿主执行器待核对的信息；本包无外部调用。不能把离线回执的submitted改true伪造执行。

状态事件只允许修改state_rules中的字段；不可变形制、身份和布局必须经新版本变更。
修改任何ArtIR、导演字节、素材、编译器或注册表后重新编译并创建新QA；旧QA不能签新回执。
`dependency-index.json`用于宿主定位影响范围。本版保守使整份QA失效，未实现自动局部重用引擎。
宿主可根据差异、依赖和旧证据决定复用未受影响资产，并将决定记录在新合同来源中。
