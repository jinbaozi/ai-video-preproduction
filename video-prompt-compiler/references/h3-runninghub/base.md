# H3 基础模式：T2VA / I2VA / FL2VA / L2VA

依据 [官方可离线技能](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/SKILL.md) 与 [基础模式指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/raw/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)，核对日期 2026-09-29。只组织已授权内容，不为“丰富”而增加剧情、演员或音乐。

## 从可观察结果反推描述

先锁定主动作和终态，再写实现它所需的主体、起始姿势、空间关系、动作路径、接触与反馈、镜头和声音。用“右手将钥匙接触桌面后松开”替代“高级电影感”；光色说明来源、受光面和变化，转焦写出起点主体→触发时刻→终点主体。景别不能同时要求不可见的微表情。

相机的运动类型、幅度、速度分开；推进不是变焦，景深变化不是主体位置变化。精确坐标、焦距或时间只能表达意图，不声称 H3 必然逐值执行。先保持原有构图和运动，再增加有依据的可见细节，避免互相矛盾的镜头词。

## 官方字段顺序

```text
integrated_multimodal_description: [Shot 1] ...
overall_soundscape: ...
non_diegetic_music: N/A
```

文字模式从首字段开始。其他模式先加关键帧对齐说明：I2VA 的 Picture 1 为开头；FL2VA 的 Picture 1 为开头、Picture 2 为结尾；L2VA 的 Picture 1 是最后一个镜头的结尾，不固定写 Shot 1。不要把尾帧当作角色参考图，更不能在没有附件时假定存在关键帧。

先核对帧数对应的实际时长再写对齐时刻。原生 Comfy 24fps 的 `length` 是帧数且向上对齐至 `17k+5`；官方托管 API 的 `duration` 是 4–15 整数秒。两者不得混为同一参数。`h3 plan` 给出帧数、实际时长和最后帧时刻；差异由宿主审阅，不自动拉伸台词/动作。

首尾帧任务默认用一个连续镜头描述可成立的起态→过渡→末态；必须跨镜时才加剪切，不靠“丝滑”掩盖人物瞬移或姿势突变。

## 镜头与声音语法

首镜写 `[Shot 1]`，不写 `At 00:00.000`。后续镜头从 2 开始递增：

```text
[Shot 2] At 00:03.500, the camera cuts to a close-up of the key.
```

时间是当前片段的局部时间；每段重新编号，切点必须严格位于片段内。连续运镜或转焦本身不是剪切，不因此增加 Shot。

稳定使用 S1/S2 作为说话人标识；语言标签写明实际语言。台词原文、标点及归属原样保留：

```text
The engineer (S1) says softly: <d>[Chinese] 终于找到了。</d>
```

声音风格、呼吸和表情写在 `<d>` 外，不让模型把说明读出来。明确画外音时使用 off-screen voiceover，并描述画面人物闭口；`<scenetrans>` 仅用于有依据的跨切延续，`<cutoff>` 仅用于刻意被截断，不默认插入。

`overall_soundscape` 放环境声与同步物理音效，不重复台词和配乐；`non_diegetic_music` 放非场景内的配乐，无配乐才写 `N/A`。场景内乐器/收音机与后期背景音乐分开。可见文字用英文双引号括起原文，避免和说话内容混淆。

## 冻结前检查

确认动作和语句能在实际片段时长内完成；每个接触有前后状态，每次转焦有可见目标，光色变化有光源或明确创作意图。`h3 lint` 只检查字段、Shot、时间、标签等结构，不证明语义正确。实际生成后逐镜复核动作方向、手别、道具、脸、口型与切点。
